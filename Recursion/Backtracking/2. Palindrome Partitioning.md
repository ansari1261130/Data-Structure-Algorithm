
# LeetCode 131 — Palindrome Partitioning

Question

LeetCode: [LeetCode 131 — Palindrome Partitioning](https://leetcode.com/problems/palindrome-partitioning/)

Given a string s, partition s such that every substring of the partition is a palindrome.

Return all possible palindrome partitionings of s.

Example:

Input:
s = "aab"

Output:
[["a","a","b"],["aa","b"]]

## 1. What Are We Building?

We are building a partition of the string.

At each recursion level, the next piece can have different lengths.

For:

s = "aab"
idx = 0

possible next pieces are:

"a"
"aa"
"aab"

Therefore the choice is not just one character.

The choice is:

substring(s, idx, i + 1)

where i is the possible ending position.

## 2. What Does idx Mean?

idx means:

The starting index of the next substring that still needs to be partitioned.

Example:

s = "aab"

Initially:

idx = 0

If we choose:

"a"

which uses index 0, then the remaining string starts at:

idx = 1

So the recursive call is:

backtrack(s, i + 1, ...)

because everything through i has already been consumed.

## 3. What Does i Mean?

Inside:

for (int i = idx; i < s.length(); i++)

i represents:

The ending index of the current candidate partition piece.

Therefore:

String word = s.substring(idx, i + 1);

means:

current piece = s[idx ... i]

Example for "aab" and idx = 0:

i = 0 → "a"
i = 1 → "aa"
i = 2 → "aab"

## 4. Why Is There a for Loop?

At one recursion level, there are multiple possible next pieces.

For:

"aab"

starting at idx = 0:

"a"
"aa"
"aab"

So the loop enumerates all possible choices:

for (int i = idx; i < s.length(); i++)

Think:

FOR LOOP
→ enumerate possible next partition pieces

RECURSION
→ explore the selected piece

## 5. Core Backtracking Pattern

The pattern is:

FOR EACH POSSIBLE PIECE
        ↓
      CHECK
        ↓
       DO
        ↓
    EXPLORE
        ↓
      UNDO
        ↓
 NEXT PIECE

For this problem:

FOR every ending i
        ↓
piece = s[idx..i]
        ↓
is palindrome?
        ↓
YES
        ↓
ADD piece
        ↓
RECURSE from i+1
        ↓
REMOVE piece

This is:

DO → EXPLORE → UNDO

## 6. Why Check Palindrome Before Recursing?

Not every substring is a valid partition piece.

For:

s = "aab"

the first-level choices are:

"a"   → palindrome ✅
"aa"  → palindrome ✅
"aab" → not palindrome ❌

If the current piece is not a palindrome, there is no reason to explore the branch.

So:

invalid choice
→ don't recurse

This is a form of pruning.

## 7. Recursion Tree for "aab"

Conceptually:

```text
backtrack(idx=0, path=[])
├── choose "a"      -> palindrome
│   └── backtrack(idx=1, path=["a"])
│       ├── choose "a"  -> palindrome
│       │   └── backtrack(idx=2, path=["a", "a"])
│       │       └── choose "b" -> palindrome
│       │           └── backtrack(idx=3, path=["a", "a", "b"])
│       │               └── save ["a", "a", "b"]
│       └── choose "ab" -> not palindrome, prune
├── choose "aa"     -> palindrome
│   └── backtrack(idx=2, path=["aa"])
│       └── choose "b" -> palindrome
│           └── backtrack(idx=3, path=["aa", "b"])
│               └── save ["aa", "b"]
└── choose "aab"    -> not palindrome, prune
```

Invalid choices are:

"aab" ❌
"ab"  ❌

So valid partitions are:

["a","a","b"]
["aa","b"]

## 9. Why Is the Base Case idx == s.length()?

A partition is complete only when the entire string has been consumed.

For:

s = "aab"

we have:

s.length() = 3

Once:

idx = 3

all characters at indices:

0,1,2

have been included in partition pieces.

Therefore:

if (idx == s.length()) {
    list.add(new ArrayList<>(subList));
    return;
}

## 10. Why Is the Base Case Different From Subsets II?

This is an important recursion distinction.

Subsets II

A current subset is already a valid subset.

For example:

[]
[1]
[1,2]

all are valid subsets.

So we can save immediately:

list.add(new ArrayList<>(subList));

at the beginning.

Palindrome Partitioning

A current partial partition may not be complete.

For:

s = "aab"

this:

["a"]

is not a complete partition.

There is still:

"ab"

to process.

Therefore we need:

idx == s.length()

before saving the final partition.

Mental rule:

Current state IS an answer
→ save now

Current state is PARTIAL work
→ keep exploring

## 11. Why subList Needs ADD → RECURSE → REMOVE

subList is mutable and shared across recursive calls.

Suppose:

subList = []

Choose:

"a"

Now:

subList = ["a"]

Explore everything below it.

When recursion returns, "a" is still in the list.

Before the parent tries another piece such as:

"aa"

we must restore the parent state:

subList = []

Therefore:

subList.add(word);

backtrack(...);

subList.remove(subList.size() - 1);

is required.

## 12. Why We Don't Need a StringBuilder

An earlier approach used a StringBuilder to create the current word.

But the current partition piece is already defined by:

idx
i

So:

String word = s.substring(idx, i + 1);

is enough.

This gives a simpler state:

idx + subList

instead of:

idx + StringBuilder + subList

Important lesson:

Carry only the state that the recursion actually needs.

## 13. Complete Code

```java
class Solution {
    public List<List<String>> partition(String s) {
        List<String> subList = new ArrayList<>();
        List<List<String>> list = new ArrayList<>();

        backtrack(s, 0, subList, list);

        return list;
    }

    private void backtrack(
            String s,
            int idx,
            List<String> subList,
            List<List<String>> list) {

        if (idx == s.length()) {
            list.add(new ArrayList<>(subList));
            return;
        }

        for (int i = idx; i < s.length(); i++) {

            String word = s.substring(idx, i + 1);

            if (isPalindrome(word)) {

                // DO
                subList.add(word);

                // EXPLORE
                backtrack(
                    s,
                    i + 1,
                    subList,
                    list
                );

                // UNDO
                subList.remove(subList.size() - 1);
            }
        }
    }

    private boolean isPalindrome(String s) {
        int i = 0;
        int j = s.length() - 1;

        while (i < j) {
            if (s.charAt(i) != s.charAt(j)) {
                return false;
            }

            i++;
            j--;
        }

        return true;
    }
}
```

## 15. What Does idx and i Together Mean?

This is one of the most useful ways to understand this recursion.

idx = beginning of current piece
i   = ending of current piece

Therefore:

current piece = s[idx..i]

After choosing that piece:

next idx = i + 1

because the next recursion must start after the selected piece.

Example:

s = "aab"

If:

idx = 0
i = 1

then:

word = "aa"

and next recursion starts at:

idx = 2

Remaining string:

"b"

## 16. Parent Loop vs Recursive i + 1

A common confusion is:

for (int i = idx; ...)

and:

backtrack(s, i + 1, ...)

These do not mean i + 2.

They belong to different recursion frames.

Example:

Parent:
idx = 0
loop i = 0
choose "a"
    ↓
Child:
idx = 1
child has its own loop
    ↓
child explores "a", "ab"
    ↓
child returns
    ↓
Parent resumes its own loop
i++ → 1
try "aa"

So:

### recursive i + 1

child's starting position

### loop i++

next sibling choice in the parent

## 17. Why Invalid Substrings Are Not Explored

Suppose:

idx = 0
i = 2
word = "aab"

If:

isPalindrome("aab") == false

then:

backtrack(...)

is not called.

That means the entire subtree below "aab" is eliminated.

This is a general backtracking principle:

Invalid choice
→ prune its whole subtree

## 18. General Backtracking Template

```java
void backtrack(int idx) {

    if (complete) {
        saveAnswer();
        return;
    }

    for (each possible choice) {

        if (choice is invalid) {
            continue;
        }

        // DO
        choose(choice);

        // EXPLORE
        backtrack(nextState);

        // UNDO
        undo(choice);
    }
}
```

For Palindrome Partitioning:

complete:
idx == s.length()

choice:
s.substring(idx, i + 1)

valid:
isPalindrome(choice)

nextState:
i + 1

undo:
remove last string from subList

## 19. How To Identify This Pattern in a New Problem

Ask:

Q1. What am I constructing?

Here:

A partition of a string.

Q2. What is one choice?

A substring starting at idx.

Q3. How many choices are possible?

Every possible ending position:

idx, idx+1, ..., n-1

So:

for(...)

Q4. Is every choice valid?

No.

Only palindromes are valid.

So:

check → prune invalid branch

Q5. What happens after choosing a piece?

The next unprocessed character is:

i + 1

Q6. What must be undone?

The chosen substring in subList.

Therefore:

ADD → RECURSE → REMOVE

Q7. When is the whole string consumed?

idx == s.length()

Then save the partition.

## 22. Complexity

Let:

n = s.length()

There can be exponentially many possible partitions.

The number of possible partition patterns is bounded by:

2^(n-1)

because each gap between adjacent characters can be either:

CUT
NO CUT

The straightforward implementation also performs palindrome checks for candidate substrings.

So the total runtime is exponential with additional polynomial work for checking candidates.

Recursion depth:

O(n)

Output space can also be exponential because the result may contain many partitions.

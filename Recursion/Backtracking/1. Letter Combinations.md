
# LeetCode 17 — Letter Combinations of a Phone Number

Question

LeetCode: [LeetCode 17 — Letter Combinations of a Phone Number](https://leetcode.com/problems/letter-combinations-of-a-phone-number/)

Given a string containing digits from 2 to 9, return all possible letter combinations that the number could represent.

Phone keypad mapping:

2 → abc
3 → def
4 → ghi
5 → jkl
6 → mno
7 → pqrs
8 → tuv
9 → wxyz

Example:

digits = "23"

Output:

["ad","ae","af","bd","be","bf","cd","ce","cf"]

## 1. First Understand the Pattern

This is a multiple-choice recursion / backtracking problem.

For every digit:

Choose one of the letters mapped to that digit.

For:

2 → abc
3 → def

the recursion tree is:

                         ""
                    /     |     
                   a      b      c
                 / | \   / | \   / | 
                d  e  f d  e  f d  e  f
                |  |  | |  |  | |  |  |
               ad ae af bd be bf cd ce cf

The important pattern is:

FOR EACH CHOICE
      ↓
     DO
      ↓
   EXPLORE
      ↓
    UNDO
      ↓
NEXT CHOICE

## 2. Why Is a for Loop Needed?

At every recursion level, there are multiple choices.

For:

digits = "23"

At index 0:

digits[0] = '2'

and:

2 → abc

So the current recursion level has three choices:

a
b
c

Therefore:

for (char c : letters.toCharArray())

enumerates those choices.

Then recursion moves to the next digit.

So:

### for loop

all possible choices for current digit

### recursion

explore the chosen letter for the next digit

## 3. There Aren't Two Explicit for Loops

A common confusion is:

"For 23, do I need one loop for 2 and another loop for 3?"

No.

You write one loop inside the recursive helper:

for (char c : letters.toCharArray()) {
    ...
}

The same loop code runs again when recursion moves to the next digit.

Example:

helper(0, "")
    ↓
current digit = 2
    ↓
loop over abc
    ↓
choose a
    ↓
helper(1, "a")
    ↓
current digit = 3
    ↓
the SAME for-loop now loops over def

So:

Parent recursion
→ loop over abc

Child recursion
→ same loop code
→ now loops over def

## 4. Parent Loop vs Child Loop

For:

digits = "23"

the execution looks like:

Parent:
helper(i=0, "")
│
├── loop chooses 'a'
│      │
│      └── Child:
│          helper(i=1, "a")
│          ├── loop chooses 'd'
│          ├── loop chooses 'e'
│          └── loop chooses 'f'
│
├── parent loop chooses 'b'
│      │
│      └── Child:
│          helper(i=1, "b")
│          ├── loop chooses 'd'
│          ├── loop chooses 'e'
│          └── loop chooses 'f'
│
└── parent loop chooses 'c'
       │
       └── Child:
           helper(i=1, "c")
           ├── loop chooses 'd'
           ├── loop chooses 'e'
           └── loop chooses 'f'

This creates:

3 × 3 = 9

combinations.

## 5. What Does i Mean?

The recursive parameter:

int i

represents:

Which digit am I processing right now?

Example:

i = 0
→ process digits[0]

i = 1
→ process digits[1]

i = 2
→ process digits[2]

When:

i == digits.length

all digits have been processed.

## 6. What Does StringBuilder sb Mean?

sb represents:

The letters chosen so far.

For:

digits = "23"

one path might be:

""
 ↓ choose a
"a"
 ↓ choose d
"ad"

At that point we have one complete answer.

## 7. Why Do We Use append() and deleteCharAt()?

StringBuilder is mutable.

We are using the same StringBuilder throughout the recursion.

Example:

sb = ""

Choose a:

sb = "a"

Choose d:

sb = "ad"

A complete answer is found.

When that recursive call returns, d is still present:

sb = "ad"

We now need to try e.

So first undo d:

sb.deleteCharAt(sb.length() - 1);

Then:

sb = "a"

and we can append e:

"ae"

Therefore:

APPEND
 ↓
RECURSE
 ↓
DELETE

This is backtracking.

## 8. Why Don't We Create a New StringBuilder Every Time?

We can reuse one mutable working path.

Create it once:

StringBuilder sb = new StringBuilder();

Then:

append
→ recurse
→ delete
→ append
→ recurse
→ delete
...

This is the same working-path idea we used with:

subList

in Subsets and Combination Sum.

## 9. Base Case

Here we do need an explicit base case:

if (i == digits.length()) {
    list.add(sb.toString());
    return;
}

Why?

Because a partial string is not yet a complete answer.

For:

digits = "23"

these are partial:

"a"
"b"
"c"

They are not final combinations.

But:

"ad"
"ae"
"af"
...

are complete.

So we wait until:

i == digits.length()

and then save the result.

## 10. Base Case Identification

Ask:

Is the current state already a complete answer?

For this problem:

"a"

No, because digit 3 still needs a letter.

Therefore keep exploring.

When:

i == digits.length()

there are no digits left.

Now:

sb

is a complete answer.

So:

list.add(sb.toString());

## 11. Compare With Subsets II

Subsets II

Every current subList is already a valid subset.

Therefore:

list.add(new ArrayList<>(subList));

is at the beginning of the function.

Then we extend it.

Letter Combinations

A partial StringBuilder is not a complete answer.

Therefore:

keep exploring

until:

i == digits.length()

Then save.

Mental rule:

Current state is already an answer
→ save now

Current state is partial work
→ keep exploring

## 12. Complete Code

class Solution {
    Map<Character, String> digitToLetter = Map.of(
        '2', "abc",
        '3', "def",
        '4', "ghi",
        '5', "jkl",
        '6', "mno",
        '7', "pqrs",
        '8', "tuv",
        '9', "wxyz"
    );

    public List<String></string> letterCombinations(String digits) {
        List<String></string> list = new ArrayList<>();

        if (digits == null || digits.isEmpty()) {
            return list;
        }

        StringBuilder sb = new StringBuilder();

        combinations(0, digits, sb, list);

        return list;
    }

    private void combinations(
            int i,
            String digits,
            StringBuilder sb,
            List<String></string> list) {

        if (i == digits.length()) {
            list.add(sb.toString());
            return;
        }

        char ch = digits.charAt(i);
        String letters = digitToLetter.get(ch);

        for (char c : letters.toCharArray()) {

            // DO
            sb.append(c);

            // EXPLORE
            combinations(i + 1, digits, sb, list);

            // UNDO
            sb.deleteCharAt(sb.length() - 1);
        }
    }
}

                                   ""

## 15. General Tree for Multiple Digits

Suppose:

digits = "234"

Mappings:

2 → abc
3 → def
4 → ghi

Conceptually:

                              ""
                  /            |                             a             b             c
              / | \         / | \         / | 
             d  e  f       d  e  f       d  e  f
            /|\ /|\ /|\   /|\ /|\ /|\   /|\ /|\ /|           ghi ...

Every recursion level processes exactly one digit.

So:

Level 0 → digit 2
Level 1 → digit 3
Level 2 → digit 4

## 16. Number of Combinations

If each digit maps to 3 letters:

3 × 3 × 3 = 3^n

If a digit such as 7 or 9 maps to 4 letters, the number depends on the product of the number of letters for each digit.

For example:

"23":
3 × 3 = 9

For:

"79":
4 × 4 = 16

This follows directly from the recursion tree branching factor.

## 17. Complexity

Let n = digits.length.

The number of generated combinations is at most:

4^n

because digits 7 and 9 have 4 letters.

Each completed string has length n.

So output construction is roughly:

O(n × 4^n)

time.

Recursion depth:

O(n)

The returned result itself can take:

O(n × 4^n)

space.

## 18. Why No remove() on the Result List?

At the leaf:

list.add(sb.toString());

we create a String.

Unlike StringBuilder, a String is immutable.

So when we later modify:

sb

the stored result does not change.

Example:

sb = "ad";

list.add(sb.toString());

The list stores:

"ad"

Then:

sb.deleteCharAt(...)

can change the builder, but the already stored "ad" remains unchanged.

This differs from:

list.add(subList);

with a mutable List.

## 21. How To Recognize This Pattern

Ask:

Q1. What am I constructing?

Here:

One letter for each input digit.

Q2. At one level, how many choices do I have?

The current digit's mapped letters:

3 or 4 choices

So:

for loop

Q3. What does the recursion index mean?

Which digit am I processing?

Q4. Does choosing one letter finish the answer?

No.

One letter handles only one digit.

So recurse to:

i + 1

Q5. Am I changing a shared path?

Yes:

StringBuilder sb

So:

append → recurse → delete

Q6. When is the answer complete?

i == digits.length()

## 22. General Multiple-Choice Backtracking Template

void backtrack(state) {

    if (complete) {
        saveAnswer();
        return;
    }

    for (choice : choices) {

        // DO
        makeChoice(choice);

        // EXPLORE
        backtrack(nextState);

        // UNDO
        undoChoice(choice);
    }
}

For this problem:

state:
i + current string

choices:
letters mapped to digits[i]

DO:
append letter

EXPLORE:
i + 1

UNDO:
delete last letter

COMPLETE:
i == digits.length()

## 23. Compare With Combination Sum II

Combination Sum II

At a level:

for i from idx to n

Choice:

choose candidate i

Then:

recurse(i + 1)

Letter Combinations

At a level:

for c in letters mapped to current digit

Choice:

choose character c

Then:

recurse(i + 1)

Same architecture:

FOR
 ↓
DO
 ↓
RECURSE
 ↓
UNDO

Only the meaning of choices changes.

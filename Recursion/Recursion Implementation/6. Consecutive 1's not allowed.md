# PART A — CORE NOTES (ORIGINAL, CORRECTED & EXPANDED)

*Your original 22 sections are preserved below. Corrections and additions are marked.*

## 1) Core idea

Given an integer `n`, count the number of binary strings of length `n` such that no two consecutive characters are `1`.

Examples:

- `n = 1` → `0`, `1` → answer = 2
- `n = 2` → `00`, `01`, `10` → answer = 3
- `n = 3` → `000`, `001`, `010`, `100`, `101` → answer = 5

The restriction is:

```text
"11" is not allowed
```

That means the next choice depends on the previous digit.

---

## 2) First observation

The restriction is not independent at each position.

If the previous digit is:

- `0` → we may add `0` or `1`
- `1` → we may add only `0`

This is the key insight.

The next choice depends on the previous one, so we need a recurrence.

---

## 3) My initial thinking

For `n = 3`, valid strings are:

```text
000
001
010
100
101
```

We can group them by ending digit:

- ending in `0` → 3 strings
- ending in `1` → 2 strings

Going to `n = 4`:

- strings ending in `0` → `3 × 2 = 6`
- strings ending in `1` → `2 × 1 = 2`

Then total = `6 + 2 = 8`.

This is correct for the example, but it can mislead me if I keep thinking in concrete numbers.

The problem is not the arithmetic itself; it is the fact that `6` and `2` are just values for one example.

I should ask:

```text
What do these numbers represent?
Can I write them in terms of the same function with a smaller input?
```

---

## 5) Generalization test

Instead of asking only about `n = 5`, ask:

```text
How do I solve for any n?
```

Define:

```text
F(n) = number of valid binary strings of length n
```

Now split all valid strings into two cases:

- ends in `0`
- ends in `1`

---

## 6) Case 1: string ends in 0

If the final character is `0`, then the first `n-1` positions can be any valid string of length `n-1`.

So:

```text
Number of strings ending in 0 = F(n - 1)
```

---

## 7) Case 2: string ends in 1

If the final character is `1`, then the previous character must be `0` because `11` is not allowed.

So the string must end as:

```text
... 0 1
```

Then the first `n-2` positions can be any valid string of length `n-2`.

So:

```text
Number of strings ending in 1 = F(n - 2)
```

---

## 8) Combine the two cases

Every valid string must end in either `0` or `1`.

Therefore:

```text
F(n) = F(n - 1) + F(n - 2)
```

This recurrence came from the choices and the smaller subproblems.

It was not guessed from Fibonacci; it was derived from the logical cases.

---

## 9) Base cases

For `n = 0`:

There is exactly one empty string:

```text
""
```

So:

```text
F(0) = 1
```

For `n = 1`:

Valid strings are:

```text
0
1
```

So:

```text
F(1) = 2
```

Final base cases:

```text
F(0) = 1
F(1) = 2
```

## 10) Recursion form

This recurrence directly becomes:

```java
countStrings(n)
    = countStrings(n - 1) + countStrings(n - 2)
```

with base cases:

```java

```

## 11) Final Java code

```java
class Solution {
    int countStrings(int n) {
        if (n == 0) return 1;
        if (n == 1) return 2;
```

## 13) Recursion tree

For `F(5)`, the tree looks like:

```text
            F(5)
           /    \
        F(4)    F(3)
       /   \    /   \
     F(3) F(2) F(2) F(1)
      / \
   F(2) F(1)
```

Notice that the same values are recomputed many times.

This is why this naive recursion is inefficient.

---

## 14) Important recursion pattern

The pattern is:

```text
CHOICES
  ↓
SPLIT INTO CASES
  ↓
SEE WHAT REMAINS
  ↓
CHECK IF IT IS THE SAME PROBLEM
  ↓
RECURSE
```

For this problem:

- choice = last digit
- if last digit is `0`, we need `F(n-1)`
- if last digit is `1`, previous digit must be `0`, so we need `F(n-2)`

This is the real transferable pattern.

## 18) Complexity

This recursive version recomputes the same states repeatedly.

So:

```text
Time Complexity = O(2^n)
```

The recursion depth is at most `n`.

So:

```text
Space Complexity = O(n)
```

> **⚠ REFINEMENT — `O(2ⁿ)` is a valid upper bound, but it is not tight.**
>
> ```text
>    The recursion tree is NOT a full binary tree.
>    The left branch goes n-1 but the right branch goes n-2, so the right
>    subtree is ALWAYS shallower. The tree is lopsided.
>
>                      F(5)
>                    /      \
>                 F(4)      F(3)          <- right side already shorter
>                /    \     /    \
>             F(3)  F(2)  F(2)  F(1)
>             /  \
>          F(2)  F(1)
>
>    Number of LEAVES = exactly F(n)
>    Number of CALLS  = 2*F(n) - 1
>
>    And F(n) grows like phi^n, where phi = (1+sqrt(5))/2 ~= 1.618
>
>    TIGHT BOUND:   Theta(phi^n)  ~=  Theta(1.618^n)
>    NOT:           Theta(2^n)
> ```
>
> Saying **`Θ(φⁿ)` — the golden ratio** instead of `O(2ⁿ)` is a real differentiator. It shows
> you analysed the tree rather than assuming "two recursive calls ⇒ `2ⁿ`".
>
> Space `O(n)` is correct — the maximum depth is the leftmost path, of length `n`.

## 23) ADDED — The optimisation ladder (four versions that actually pass)

This problem is the **perfect** demonstration of the standard DP progression. Walk an
interviewer up this ladder out loud — it's worth more than jumping to the final answer.

```text
   THE LADDER

   1. NAIVE RECURSION      Theta(phi^n) time, O(n) space    <- your §11 (derivation only)
            |  "I'm recomputing F(3) many times"
            v
   2. MEMOISATION          O(n) time, O(n) space + O(n) stack
            |  "the recursion is just filling an array left to right"
            v
   3. BOTTOM-UP TABLE      O(n) time, O(n) space, no recursion
            |  "I only ever look back two cells"
            v
   4. ROLLING VARIABLES    O(n) time, O(1) space            <- SHIP THIS
            |  "n could be 10^18"
            v
   5. MATRIX EXPONENTIATION  O(log n) time, O(1) space      <- see §25
```

### Version 2 — Memoisation (top-down)

```java
class Solution {
    private static final int MOD = 1_000_000_007;

    int countStrings(int n) {
        long[] memo = new long[n + 1];
        Arrays.fill(memo, -1);
        return (int) solve(n, memo);
    }

    private long solve(int n, long[] memo) {
        if (n == 0) return 1;
        if (n == 1) return 2;
        if (memo[n] != -1) return memo[n];

        return memo[n] = (solve(n - 1, memo) + solve(n - 2, memo)) % MOD;
    }
}
```

```text
   WHAT MEMOISATION ACTUALLY DID

   BEFORE: F(5) called F(3) TWICE, F(2) THREE times, F(1) FIVE times
   AFTER : each F(k) computed EXACTLY ONCE, then read from the array

   Theta(phi^n)  ->  O(n)      because there are only n distinct states
```

### Version 3 — Bottom-up table

```java
int countStrings(int n) {
    final int MOD = 1_000_000_007;
    if (n == 0) return 1;
    if (n == 1) return 2;

    long[] dp = new long[n + 1];
    dp[0] = 1;
    dp[1] = 2;
    for (int i = 2; i <= n; i++) {
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD;
    }
    return (int) dp[n];
}
```

### Version 4 — Rolling variables · `O(1)` space · **ship this**

```java
int countStrings(int n) {
    final int MOD = 1_000_000_007;
    if (n == 0) return 1;
    if (n == 1) return 2;

    long prev2 = 1;   // F(0)
    long prev1 = 2;   // F(1)

    for (int i = 2; i <= n; i++) {
        long cur = (prev1 + prev2) % MOD;
        prev2 = prev1;
        prev1 = cur;
    }
    return (int) prev1;
}
```

```text
   WHY ONLY TWO VARIABLES ARE NEEDED

   dp[i] = dp[i-1] + dp[i-2]
            ^^^^^^   ^^^^^^
            only these two cells are ever read.
   dp[i-3] and older are DEAD. Storing them is pure waste.

        i=2   [F0][F1] -> F2
        i=3        [F1][F2] -> F3        the window SLIDES
        i=4             [F2][F3] -> F4
                        ^^^^^^^^
                        always exactly 2 cells

   O(n) array  ->  O(1) two longs
```

```text
   WHY `long` AND NOT `int`

   Both operands are < MOD = 1e9+7.
   Their SUM can reach ~2e9, which EXCEEDS Integer.MAX_VALUE (2.147e9).

   long prev1, prev2  ->  the sum is safe, then % MOD brings it back down.
   Cast to int only at the very end, after the final reduction.
```

## 24) ADDED — The two-state DP (formalising your §3 instinct)

In §3 you counted "strings ending in 0" and "strings ending in 1" — then abandoned that view.
**It was correct**, and it generalises far better than the collapsed recurrence. Formalise it.

```text
   DEFINE TWO STATES:

      end0[i] = number of valid strings of length i that END in 0
      end1[i] = number of valid strings of length i that END in 1

   TRANSITIONS (think: "what can I append?"):

      to end in 0  ->  the previous char can be ANYTHING
                       end0[i] = end0[i-1] + end1[i-1]

      to end in 1  ->  the previous char MUST be 0
                       end1[i] = end0[i-1]

   ANSWER:  F(n) = end0[n] + end1[n]

   BASE:    end0[1] = 1   ("0")
            end1[1] = 1   ("1")
```

```java
int countStrings(int n) {
    final int MOD = 1_000_000_007;
    long end0 = 1, end1 = 1;              // length 1: "0" and "1"

    for (int i = 2; i <= n; i++) {
        long newEnd0 = (end0 + end1) % MOD;   // append 0 to anything
        long newEnd1 = end0;                   // append 1 only after a 0
        end0 = newEnd0;
        end1 = newEnd1;
    }
    return (int) ((end0 + end1) % MOD);
}
```

```text
   THE TABLE (watch both columns)

   i  | end0 | end1 | total F(i)
   ---+------+------+------------
   1  |   1  |   1  |     2
   2  |   2  |   1  |     3
   3  |   3  |   2  |     5
   4  |   5  |   3  |     8
   5  |   8  |   5  |    13

   Notice: end0 and end1 are BOTH Fibonacci, just shifted.
           And end1[i] = end0[i-1] exactly.

   SUBSTITUTING end1[i] = end0[i-1] into end0[i] = end0[i-1] + end1[i-1]:
        end0[i] = end0[i-1] + end0[i-2]
   ...which is why the whole thing collapses to ONE Fibonacci recurrence. ✓
```

> **Why keep the two-state version if it collapses?** Because it **survives generalisation**
> and the collapsed form does not:
>
> ```text
>   "no THREE consecutive 1s"  -> track end00, end01, end10, end11 (last TWO chars)
>   "no two consecutive 1s AND no two consecutive 0s" -> same two states, different
>                                                         transitions
>   "alphabet of size k"       -> k states
>   "no two adjacent equal"    -> k states, transition to any of the other k-1
> ```
>
> The collapsed `F(n-1)+F(n-2)` is a lucky simplification. The **state machine is the real
> model.** Interviewers who ask a follow-up are testing exactly this.

## 25) ADDED — `O(log n)` via matrix exponentiation (reusing notes 2 and 3)

If `n` were `10¹⁸`, even `O(n)` is too slow. Any **linear recurrence** can be lifted to a
matrix power — and you already know how to compute those fast.

```text
   WRITE THE RECURRENCE AS A MATRIX

        | F(n)   |     | 1  1 |   | F(n-1) |
        |        |  =  |      | * |        |
        | F(n-1) |     | 1  0 |   | F(n-2) |

   Apply it n-1 times:

        | F(n)   |     | 1  1 |^(n-1)   | F(1) |     | 1 1 |^(n-1)   | 2 |
        |        |  =  |      |       * |      |  =  |     |       * |   |
        | F(n-1) |     | 1  0 |         | F(0) |     | 1 0 |         | 1 |

   Computing M^(n-1) by BINARY EXPONENTIATION (your Pow(x,n) note!) is O(log n).
```

```java
class Solution {
    private static final long MOD = 1_000_000_007L;

    int countStrings(int n) {
        if (n == 0) return 1;
        if (n == 1) return 2;

        long[][] result = matPow(new long[][] {{1, 1}, {1, 0}}, n - 1);
        // result * [F(1), F(0)] = [F(n), F(n-1)]
        return (int) ((result[0][0] * 2 + result[0][1] * 1) % MOD);
    }

    private long[][] matPow(long[][] base, long exp) {
        long[][] result = {{1, 0}, {0, 1}};      // identity matrix
        while (exp > 0) {
            if ((exp & 1) == 1) result = multiply(result, base);
            base = multiply(base, base);
            exp >>= 1;
        }
        return result;
    }

    private long[][] multiply(long[][] a, long[][] b) {
        long[][] c = new long[2][2];
        for (int i = 0; i < 2; i++)
            for (int j = 0; j < 2; j++)
                for (int k = 0; k < 2; k++)
                    c[i][j] = (c[i][j] + a[i][k] * b[k][j]) % MOD;
        return c;
    }
}
```

```text
   NOTICE WHAT matPow IS

   long[][] result = IDENTITY;
   while (exp > 0) {
       if ((exp & 1) == 1) result = multiply(result, base);
       base = multiply(base, base);
       exp >>= 1;
   }

   THIS IS LITERALLY YOUR Pow(x,n) ITERATIVE CODE.
   Only two substitutions:
        double 1.0   ->  identity matrix
        x * y        ->  matrix multiply

   Binary exponentiation needs ONLY associativity + an identity.
   Matrix multiplication has both. So the algorithm transfers UNCHANGED.

   THIS IS THE PAYOFF FOR NOTES 2 AND 3.
```

## 26) ADDED — The exact Fibonacci relationship

Your `F` is Fibonacci, **shifted by two**. Pin it down so you can answer precisely.

```text
   STANDARD FIBONACCI (1-indexed):
        Fib: 1, 1, 2, 3, 5, 8, 13, 21, 34, ...
        idx: 1  2  3  4  5  6   7   8   9

   THIS PROBLEM:
        F(0)=1  F(1)=2  F(2)=3  F(3)=5  F(4)=8  F(5)=13
                 |       |       |       |       |
        Fib:  Fib(2)  Fib(3)  Fib(4)  Fib(5)  Fib(6)  Fib(7)
              =1      =2      =3      =5      =8      =13

   THEREFORE:      F(n) = Fib(n + 2)
```

```text
   THE COMBINATORIAL IDENTITY (a different, beautiful derivation)

   A valid string of length n has k ones, NO TWO ADJACENT.
   Placing k non-adjacent 1s among n positions can be done in
   C(n - k + 1, k) ways.

   So:     F(n) = SUM over k>=0 of  C(n - k + 1, k)

   Check n = 4:
        k=0:  C(5,0) = 1      ->  0000
        k=1:  C(4,1) = 4      ->  1000,0100,0010,0001
        k=2:  C(3,2) = 3      ->  1010,1001,0101
        k=3:  C(2,3) = 0      ->  impossible (needs >= 5 positions)
        TOTAL = 1 + 4 + 3 = 8   ✓  = F(4)

   This is the "shallow diagonal of Pascal's triangle sums to Fibonacci"
   identity. Mentioning it shows genuine mathematical depth.
```

> **Why this matters in an interview:** if asked *"isn't this just Fibonacci?"*, the weak answer
> is "yes". The strong answer is: *"It's `Fib(n+2)` with the standard 1-indexed convention —
> but I derived it from the last-character case split rather than pattern-matching, which is
> what lets me handle the follow-up where three consecutive 1s are banned and the answer
> becomes a Tribonacci-style recurrence."*

# PHASE 2 — CONCEPT REBUILDING

## CONCEPT 1: Derive, Don't Recognise (Choices → Cases → Smaller Problem)

### LEVEL 1 — Beginner Intuition

**Why does it exist?** Because pattern-matching ("this looks like Fibonacci") fails the moment
the problem changes slightly. Deriving works every time.

```text
   THE RECIPE — four questions, always in this order

   1. WHAT IS THE LAST DECISION I MAKE?
          -> here: the last character is 0 or 1

   2. SPLIT ALL SOLUTIONS BY THAT DECISION (exhaustive + disjoint)
          -> every valid string ends in 0, OR ends in 1. Never both. Never neither.

   3. FOR EACH CASE, WHAT IS LEFT OVER?
          -> ends in 0: the first n-1 chars, any valid string  -> F(n-1)
          -> ends in 1: the char before MUST be 0, so the first
                        n-2 chars are any valid string          -> F(n-2)

   4. IS THE LEFTOVER THE SAME PROBLEM, SMALLER?
          -> YES. So ADD the cases:  F(n) = F(n-1) + F(n-2)
```

**The two rules that make the split valid:**

```text
   EXHAUSTIVE — every solution falls into at least one case  (nothing missed)
   DISJOINT   — no solution falls into two cases             (nothing double-counted)

   Here: a string's last character is EITHER 0 or 1. Both rules hold. ✓
   If your cases overlap, you must subtract the overlap (inclusion-exclusion).
```

### LEVEL 2 — Mental Visualization

```text
   THE CASE SPLIT, DRAWN

   All valid strings of length n
                |
     +----------+----------+
     |                     |
   end in 0              end in 1
     |                     |
   [ any valid ] 0       [ any valid ] 0 1
    \__________/          \__________/
      length n-1            length n-2
         |                      |
       F(n-1)                 F(n-2)
         |                      |
         +----------+-----------+
                    |
              F(n) = F(n-1) + F(n-2)


   WHY "ends in 1" FORCES TWO CHARACTERS:

        ? ? ? ? 1        <- if the last char is 1...
                ^
        ? ? ? 0 1        <- ...the one before it MUST be 0 (no "11")
              ^
        \_____/          <- so only n-2 chars are actually FREE
         free
```

**Concrete enumeration for `n = 4` (verify the split by hand):**

```text
   ALL 8 VALID STRINGS OF LENGTH 4

   ENDING IN 0 (5 of them)      ENDING IN 1 (3 of them)
   -----------------------      -----------------------
   0000                         0001
   0010                         0101
   0100                         1001
   1000
   1010

   5 = F(3) ✓    (valid strings of length 3: 000,001,010,100,101)
   3 = F(2) ✓    (valid strings of length 2: 00,01,10)

   5 + 3 = 8 = F(4)   ✓

   CHECK THE MAPPING:
       "0001" with the trailing "01" removed -> "00"  (a valid length-2 string)
       "0101" -> "01"    "1001" -> "10"
       Exactly the 3 valid strings of length 2. The bijection is PERFECT.
```

**The recursion tree (and its waste):**

```text
                        F(5)
                   /            \
               F(4)              F(3)
             /      \           /     \
          F(3)      F(2)     F(2)     F(1)
         /    \    /    \    /   \
      F(2)  F(1) F(1)  F(0) F(1) F(0)
     /    \
   F(1)  F(0)

   F(3) computed 2x | F(2) computed 3x | F(1) computed 5x | F(0) computed 3x

   Calls = 2*F(5) - 1 = 2*13 - 1 = 25    for just n = 5
   For n = 50:  ~2 * 2.0e10 = 40 BILLION calls

   DISTINCT STATES: only 6 (F(0)..F(5))
   => memoisation collapses Theta(phi^n) to O(n)
```

### LEVEL 3 — Real-World Analogy

> **Climbing stairs.** You can take 1 or 2 steps. To count the ways to reach step `n`, you ask:
> *what was my last move?* Either a 1-step (from `n−1`) or a 2-step (from `n−2`). Add them.
> Identical structure — which is why Climbing Stairs is the same problem.

> **Tiling a 1×n corridor** with 1×1 and 1×2 tiles. Look at the **last tile**: if it's 1×1, the
> rest is `F(n−1)`; if it's 1×2, the rest is `F(n−2)`.

> **Seating with a rule: no two friends adjacent.** For each seat you decide occupied/empty,
> and "occupied" forces the previous seat empty. Exactly this problem.

> **Why deriving beats recognising:** a locksmith who *memorised* 50 locks is stuck on lock 51.
> A locksmith who understands *how locks work* opens all of them.

### LEVEL 4 — Interview Explanation (30 seconds)

> *"I'd derive the recurrence rather than pattern-match it. I look at the **last character**,
> because that's where the constraint lives. Every valid string ends in either 0 or 1 —
> exhaustive and disjoint. If it ends in 0, the preceding `n−1` characters can be any valid
> string, giving `F(n−1)`. If it ends in 1, the character before it is forced to be 0 by the
> no-`11` rule, so only the first `n−2` characters are free, giving `F(n−2)`. Adding the
> disjoint cases: `F(n) = F(n−1) + F(n−2)`, with `F(0)=1` for the empty string and `F(1)=2`.
> It happens to be `Fib(n+2)`, but I'd rather derive it — because if the rule became 'no three
> consecutive 1s', the same method immediately gives a three-term recurrence, whereas
> recognising Fibonacci gives me nothing."*

## CONCEPT 2: DP State Design — "What Must I Remember?"

### LEVEL 1 — Beginner Intuition

**Why does it exist?** Because the whole art of DP is deciding **how little of the past you
need to carry forward.** Too little and you can't enforce the constraint; too much and your
state space explodes.

```text
   THE QUESTION: to extend a valid string, what do I need to know about it?

   ✗ The whole string?          -> 2^n states. Useless.
   ✗ How many 1s it has?        -> doesn't tell me if I can append a 1.
   ✓ Just the LAST character    -> EXACTLY enough. 2 states.

   +--------------------------------------------------------------+
   |  THE CONSTRAINT DEFINES THE STATE.                           |
   |  "no two consecutive 1s" looks back exactly ONE character,    |
   |  so the state is exactly ONE character.                       |
   +--------------------------------------------------------------+
```

### LEVEL 2 — Mental Visualization

```text
   THE STATE MACHINE (this IS the problem)

                append 0
              +-----------+
              |           v
          +--------+   +--------+
          | END 0  |   | END 1  |
          +--------+   +--------+
              ^  |         |  ^
              |  | append 1|  |
              |  +---------+  |
              |                |
              +----------------+
                   append 0

   FULL TRANSITION TABLE:

        FROM        APPEND 0      APPEND 1
        --------    ----------    -------------
        END 0   ->  END 0    ✓    END 1     ✓
        END 1   ->  END 0    ✓    FORBIDDEN ✗   ("11")

   Three legal transitions out of four. THAT single missing arrow
   is the entire problem.
```

```text
   HOW THE COUNTS FLOW (n = 1 to 5)

   i=1     end0=1 ----\    /---- end0=2     i=2
           end1=1 ----(----+
                       \
                        \-- end1=1

           end0[i] = end0[i-1] + end1[i-1]      (both arrows in)
           end1[i] = end0[i-1]                  (only ONE arrow in)

   i :    1     2     3     4     5
   end0:  1     2     3     5     8
   end1:  1     1     2     3     5
   tot :  2     3     5     8    13

   Both rows are Fibonacci. end1 is just end0 shifted by one.
```

```text
   HOW THE STATE GROWS WITH THE CONSTRAINT

   +-------------------------------+-------------------+-------------+
   | CONSTRAINT                    | MUST REMEMBER     | # STATES    |
   +-------------------------------+-------------------+-------------+
   | no two consecutive 1s         | last 1 char       | 2           |
   | no THREE consecutive 1s       | last 2 chars      | 4 (or 3)    |
   | no k consecutive 1s           | run length so far | k           |
   | no two adjacent equal, size m | last char         | m           |
   | at most j ones total          | last char + count | 2*(j+1)     |
   +-------------------------------+-------------------+-------------+

   THE RULE: the state is the MINIMUM information about the prefix
             that determines which extensions are legal.
```

### LEVEL 3 — Real-World Analogy

> **A traffic light.** To know what's legal next, you don't need the light's entire history —
> only its **current colour**. That's the state. Everything before is irrelevant.

> **A chess draw rule.** To detect a threefold repetition you must remember all past positions.
> To know which moves are legal *right now*, you only need the current board. Different
> questions demand different state.

> **Packing a suitcase with a weight limit.** You don't need to remember which items you packed
> — only the **total weight so far**. That's a knapsack state.

### LEVEL 4 — Interview Explanation (30 seconds)

> *"The DP state comes straight from the constraint. 'No two consecutive 1s' looks back exactly
> one character, so the only thing I need to remember about a prefix is its **last character** —
> that's a two-state machine. From `end0` I can append either digit; from `end1` I can only
> append 0. That gives `end0[i] = end0[i−1] + end1[i−1]` and `end1[i] = end0[i−1]`. Substituting
> one into the other collapses it to `F(n) = F(n−1) + F(n−2)`. I prefer keeping the two states
> explicitly, because if the rule became 'no three consecutive 1s' I'd just widen the state to
> the last two characters and the method is unchanged."*

## CONCEPT 3: The Optimisation Ladder (Recursion → `O(1)` → `O(log n)`)

### LEVEL 1 — Beginner Intuition

**Why does it exist?** Because the naive recursion isn't *wrong* — it's just **slow**, and the
fix is mechanical once you see *why* it's slow: it recomputes identical states.

```text
   THE DIAGNOSIS AND THE CURE

   SYMPTOM:  F(3) is computed over and over
   CAUSE:    the recursion has OVERLAPPING SUBPROBLEMS
   CURE 1:   remember answers          -> MEMOISATION      -> O(n)
   CURE 2:   compute them in order     -> TABULATION       -> O(n), no stack
   CURE 3:   notice you only need 2    -> ROLLING VARS     -> O(1) space
   CURE 4:   notice it's linear-algebraic -> MATRIX POWER  -> O(log n)
```

### LEVEL 2 — Mental Visualization

```text
   THE SAME COMPUTATION, FOUR WAYS  (n = 5)

   1. NAIVE — 25 calls, massive duplication
        F(5)
        ├── F(4)
        │   ├── F(3)      <- computed here
        │   │   ├── F(2)
        │   │   └── F(1)
        │   └── F(2)      <- and AGAIN
        └── F(3)          <- and AGAIN

   2. MEMOISED — 6 computations, 19 cache hits
        memo: [1][2][3][5][8][13]
               0  1  2  3  4   5
        each cell filled ONCE, then read

   3. TABULATION — same array, filled left to right, no recursion
        dp[0]=1  dp[1]=2  dp[2]=3  dp[3]=5  dp[4]=8  dp[5]=13
        --------> direction of computation

   4. ROLLING — the array was never needed
        [1][2]      -> 3
           [2][3]   -> 5
              [3][5]-> 8
                 [5][8] -> 13
        a 2-cell WINDOW slides forward.  O(1) space.
```

```text
   WHEN TO USE WHICH — decided by the CONSTRAINT, not by taste

   +------------------+---------------------------+------------------------+
   |  n (constraint)  |  REQUIRED COMPLEXITY      |  APPROACH              |
   +------------------+---------------------------+------------------------+
   |  n <= 20         |  exponential is fine      |  naive recursion       |
   |  n <= 10^3       |  O(n^2) fine              |  memo / tabulation     |
   |  n <= 10^7       |  O(n)                     |  ROLLING VARS ✓        |
   |  n <= 10^18      |  O(log n)                 |  MATRIX EXPONENTIATION |
   +------------------+---------------------------+------------------------+

   READ THE CONSTRAINT FIRST. It tells you which rung to climb to.
   GFG gives n <= 10^5  ->  rolling variables is exactly right.
```

### LEVEL 3 — Real-World Analogy

> **Doing your homework.** Naive recursion is re-deriving the same sub-answer every time it
> appears. Memoisation is **writing it in the margin** the first time. Tabulation is doing the
> exercises **in order** so the answer you need is always already above. Rolling variables is
> realising you only ever look at the **previous two lines** — so you stop keeping the notebook.

> **Restocking a shop.** You don't need the full sales history to order tomorrow's stock —
> just the last couple of days. Keeping ten years of records to read two of them is the `O(n)`
> array you didn't need.

### LEVEL 4 — Interview Explanation (30 seconds)

> *"The naive recursion is `Θ(φⁿ)` because it recomputes overlapping subproblems — but there
> are only `n` distinct states, so memoising drops it to `O(n)`. Since each state depends only
> on smaller ones, I can flip it to a bottom-up loop and avoid the recursion entirely. And
> because `dp[i]` only reads `dp[i−1]` and `dp[i−2]`, I don't need the array at all — two
> rolling variables give `O(n)` time and `O(1)` space, which is what I'd ship for `n ≤ 10⁵`.
> If `n` could reach `10¹⁸`, I'd lift the recurrence into a 2×2 matrix and use binary
> exponentiation for `O(log n)`."*

## CONCEPT 4: Modular Arithmetic and Exponential Growth

### LEVEL 1 — Beginner Intuition

**Why is there a modulus?** Because the answer **explodes**. `F(n) ≈ φⁿ`, so the count has
roughly `0.209 × n` digits. At `n = 10⁵` the answer has over **20,000 digits** — it cannot fit
in any primitive type.

```text
   THE GROWTH

   n      F(n)                      digits
   ---    ----------------------    ------
   10     144                       3
   20     17,711                     5
   44     1,836,311,903             10   <- LAST int-safe value
   45     2,971,215,073             10   <- OVERFLOWS int
   92     ~7.5e18                   19   <- last long-safe value
   93     OVERFLOWS long
   10^5   ~20,900 digits            !!!

   => the problem MUST ask for a modulus, or the answer is unrepresentable.
```

### LEVEL 2 — Mental Visualization

```text
   WHERE THE OVERFLOW HIDES — even WITH a modulus

   Both dp[i-1] and dp[i-2] are < MOD = 1,000,000,007
   Their SUM can reach          ~2,000,000,012

   int  max = 2,147,483,647      <- 2.00e9 < 2.147e9, so it JUST fits...
                                    ...but with almost no margin, and any
                                    change (e.g. adding a third term for
                                    "no three consecutive 1s") BREAKS IT.

   long max = 9,223,372,036,854,775,807   <- enormous margin ✓

   +--------------------------------------------------------------+
   |  USE long FOR THE ACCUMULATOR. ALWAYS.                       |
   |  Cast to int ONCE, at the very end, after the final % MOD.   |
   +--------------------------------------------------------------+

   For a THREE-term recurrence (no three consecutive 1s):
        3 * (MOD-1) ~= 3.0e9  >  Integer.MAX_VALUE   -> int DEFINITELY breaks
```

```text
   WHY REDUCING EVERY STEP IS LEGAL

   (a + b) mod m  ==  ((a mod m) + (b mod m)) mod m

   Addition commutes with taking the remainder, so you may reduce
   after EVERY step. Values never grow. The final answer is identical.

   THE CLOCK: keep the hand's position, discard the laps.
```

### LEVEL 3 — Real-World Analogy

> **Compound interest / rice on a chessboard.** Doubling (or `φ`-ing) looks harmless at first
> and becomes astronomical fast. `F(100)` already exceeds the number of grains in the classic
> chessboard legend.

> **The modulus is a clock face.** You never record how many laps the hand made — only where it
> points. The number never grows past 12.

> **A bucket you empty continuously** rather than letting it fill and burst.

### LEVEL 4 — Interview Explanation (30 seconds)

> *"The count grows like `φⁿ`, so at `n = 10⁵` the exact answer has about 20,000 digits — it
> can't be stored in any primitive. That's why the problem asks for the result modulo `10⁹+7`.
> Modular reduction distributes over addition, so I reduce at every step and values never
> exceed `10⁹`. One detail that bites people: the sum of two reduced values reaches about
> `2×10⁹`, which is uncomfortably close to `Integer.MAX_VALUE`, so I accumulate in a `long` and
> cast to `int` only at the end. For a three-term recurrence it would overflow `int` outright."*

## 2. STORY METHOD

### The Master Story: **THE CINEMA WITH THE SHY RULE**

> A cinema has a single row of `n` seats. Each seat is either **empty (0)** or **occupied (1)**.
> House rule: **no two occupied seats may be adjacent.** How many seating arrangements exist?
>
> **The wrong instinct.** The manager starts listing arrangements. For 5 seats it's manageable.
> For 100 seats he'd still be listing when the cinema is demolished.
>
> **The right question — asked at the END of the row.** Instead of building left to right, he
> looks at the **last seat** and asks: *what is it?*
>
> - **If the last seat is EMPTY (0):** it imposes nothing. The first `n−1` seats can be arranged
>   in any valid way at all. That's `F(n−1)`.
> - **If the last seat is OCCUPIED (1):** the rule instantly forces the seat *before* it to be
>   empty. Those **two** seats are now spoken for — `…01`. Only the first `n−2` seats are free.
>   That's `F(n−2)`.
>
> Every arrangement is one or the other. Never both, never neither. So he **adds**:
> **`F(n) = F(n−1) + F(n−2)`.**
>
> **The key line:** *"A 1 never travels alone — it always drags a 0 in front of it."* That single
> sentence is the whole recurrence.
>
> **The manager's mistake he almost made.** He nearly wrote `6 × 2 + 2 × 1` from a worked
> example and called it a formula. He caught himself and asked: *"What do 6 and 2 actually
> mean?"* They were `F(4)` and `F(3)` in disguise. **Concrete numbers hide the general truth.**
>
> **The bookkeeping.** For 100,000 seats, the number of arrangements has 20,000 digits. No
> ledger holds it, so he records it **modulo `1,000,000,007`** — keeping the clock hand's
> position and discarding the laps.
>
> **The efficiency.** He first computes each `F(k)` by re-deriving everything below it, which
> takes forever. Then he realises he already worked out `F(3)` five times. He writes each result
> in the margin — and finally notices he only ever glances at the **previous two lines**, so he
> throws the notebook away and keeps two numbers.

```text
   SEAT:   1    2    3    4    5    ...   n-2  n-1   n
```

### Mini-story: **The `6 × 2 + 2 × 1` trap**

> A student proudly presents `6 × 2 + 2 × 1 = 8`. Asked *"what is 6?"* he cannot say. He has
> computed an **instance**, not a **function**. The moment he names them — `6 = F(4)`,
> `2 = F(3)` — the general formula appears by itself. **Naming your numbers is the whole trick.**

### Mini-story: **The traffic light**

> A driver approaching a junction doesn't need to know every colour the light has shown today.
> Only the **current** one determines what's legal. Your DP state is the current colour — no
> more, no less.

### Mini-story: **The folded paper, again**

> For a cinema with `10¹⁸` seats, even counting one seat at a time is hopeless. But the seating
> rule is *linear*, so it can be written as a 2×2 matrix — and matrices can be **folded** exactly
> like paper (binary exponentiation). Sixty foldings and it's done.

## 3. VISUAL MEMORY CARDS

```text
+==============================================================================+
| MEMORY CARD 1 — DERIVE, DON'T RECOGNISE                                      |
+==============================================================================+
| Concept        : Split all solutions by the LAST decision; for each case ask |
|                  what smaller version of the SAME problem remains.           |
| When to Use    : EVERY counting / DP recurrence you ever derive.             |
| Complexity     : the derivation is free; it tells you the recurrence.        |
| Key Trick      : CHOICES -> CASES (exhaustive + disjoint) -> WHAT REMAINS?   |
|                  -> SAME SMALLER PROBLEM? -> ADD (or multiply) the cases     |
| Common Mistake : Pattern-matching "this is Fibonacci" and being stuck when   |
|                  the constraint changes. Also: overlapping (non-disjoint)    |
|                  cases -> double counting.                                   |
| Memory Hook    : "WHAT WAS MY LAST MOVE?"                                    |
| Warning sign   : manipulating concrete numbers (6 x 2 + 2 x 1) = you are     |
|                  solving an EXAMPLE, not the PROBLEM. Name the numbers.      |
+==============================================================================+

+==============================================================================+
| MEMORY CARD 2 — DP STATE DESIGN                                              |
+==============================================================================+
| Concept        : The state is the MINIMUM info about the prefix that decides |
|                  which extensions are legal. The CONSTRAINT defines it.      |
| When to Use    : Every DP. Get this wrong and nothing else can save you.     |
| Complexity     : O(states x transitions)                                     |
| Key Trick      : "no two consecutive 1s" looks back 1 char -> state = 1 char |
|                  end0[i] = end0[i-1] + end1[i-1]                             |
|                  end1[i] = end0[i-1]                                          |
| Common Mistake : Carrying too much (whole string -> 2^n states) or too       |
|                  little (can't enforce the rule).                            |
| Memory Hook    : TRAFFIC LIGHT — only the CURRENT colour matters.            |
| Generalises to : no 3 consecutive -> last 2 chars | alphabet k -> k states   |
+==============================================================================+

+==============================================================================+
| MEMORY CARD 3 — THE OPTIMISATION LADDER                                      |
+==============================================================================+
| Concept        : naive -> memo -> tabulate -> roll -> matrix power           |
| When to Use    : Any recurrence with overlapping subproblems.                |
| Complexity     : Theta(phi^n) -> O(n)/O(n) -> O(n)/O(n) -> O(n)/O(1)         |
|                  -> O(log n)/O(1)                                            |
| Key Trick      : dp[i] reads only dp[i-1], dp[i-2] => keep TWO variables     |
| Common Mistake : Submitting the naive version; forgetting the modulus;       |
|                  using int for the accumulator.                              |
| Memory Hook    : WRITE IT IN THE MARGIN, then throw the notebook away.       |
| Pick by n      : n<=20 naive | n<=1e7 rolling | n<=1e18 matrix power         |
+==============================================================================+

+==============================================================================+
| MEMORY CARD 4 — THE Consecutive 1's PROBLEM ITSELF                           |
+==============================================================================+
| Concept        : Count length-n binary strings with no "11", mod 1e9+7.      |
| When to Use    : GFG Consecutive 1s; LC 70/198/213/600 all share the shape.  |
| Complexity     : Time O(n) rolling | O(log n) matrix | Space O(1)            |
| Key Trick      : LAST DIGIT DECIDES                                          |
|                  ends 0 -> F(n-1)  |  ends 1 -> forced "...01" -> F(n-2)     |
|                  F(n) = F(n-1) + F(n-2),  F(0)=1, F(1)=2                     |
| Common Mistake : submitting Theta(phi^n); no modulus; int overflow at n=45;  |
|                  wrong base cases (F(1)=2, NOT 1).                           |
| Memory Hook    : THE CINEMA WITH THE SHY RULE — a 1 drags a 0 with it.       |
| Identity       : F(n) = Fib(n+2)   [1-indexed Fib: 1,1,2,3,5,...]            |
+==============================================================================+
```

# PHASE 4 — INTERVIEW PATTERN RECOGNITION

## WHEN TO USE: Split-by-Last-Decision (recurrence derivation)

```text
   USE WHEN:

   ✓ The question asks "HOW MANY ..." (count, not list)
   ✓ Solutions are built as a SEQUENCE of decisions
   ✓ A constraint links ADJACENT decisions
   ✓ You can name a function F(n) and ask "what remains after the last choice?"
   ✓ The cases can be made EXHAUSTIVE and DISJOINT

   DO NOT USE WHEN:

   ✗ The choices are fully INDEPENDENT -> just multiply (see note 3)
   ✗ You must OUTPUT the objects -> backtracking
   ✗ Cases overlap -> you need inclusion-exclusion, not simple addition
   ✗ The constraint is global (e.g. "total ones must be prime") -> add state
```

## WHEN TO USE: DP over positions with state

```text
   ✓ A constraint looks back a FIXED, SMALL distance
   ✓ You can describe a prefix by a small summary (last char, run length, count)
   ✓ n is large (10^5, 10^6) so exponential search is impossible
   ✓ "modulo 10^9+7" appears -> almost always a counting DP
   ✓ You can draw a STATE MACHINE of legal transitions
```

## INTERVIEW TRIGGER WORDS

```text
+==========================================================================+
|  TRIGGER WORDS                              =>  THINK                    |
+==========================================================================+
|  "no two consecutive/adjacent"              =>  2-STATE DP -> FIBONACCI  |
```

```text
   ARE ADJACENT CHOICES LINKED?   This single question routes everything.

   "even index -> even digit"            "no two consecutive 1s"
```

# PHASE 5 — PROBLEM IDENTIFICATION SYSTEM

## The Master Mapping for THIS problem

```text
   Consecutive 1's Not Allowed
            ↓
   Observation: "count", n up to 10^5, constraint links ADJACENT positions
            ↓
   Pattern: Split by last decision → linear recurrence → DP
            ↓
   Data Structure: two long variables (rolling window)
            ↓
   Algorithm: F(n) = F(n-1) + F(n-2) mod 1e9+7, iterative
            ↓
   Complexity: O(n) time | O(1) space   (O(log n) via matrix power)
```

## Mapping Library — build the reflex

```text
1.  Count binary strings, no two consecutive 1s
       ↓ adjacent dependency, count
       ↓ Split-by-Last-Decision Pattern
       ↓ two rolling longs
       ↓ F(n) = F(n-1) + F(n-2)
       ↓ O(n) time, O(1) space

2.  Climbing stairs, 1 or 2 steps  (LC 70)
       ↓ last move was 1 or 2
       ↓ Same Recurrence Pattern
       ↓ two variables
       ↓ f(n) = f(n-1) + f(n-2)
       ↓ O(n) time, O(1) space

3.  House Robber  (LC 198)
       ↓ can't take adjacent
       ↓ Take-or-Skip DP Pattern
       ↓ two variables
       ↓ f(i) = max(f(i-1), f(i-2) + v[i])
       ↓ O(n) time, O(1) space

4.  Count binary strings, no THREE consecutive 1s
       ↓ looks back two characters
       ↓ Widened-State DP Pattern
       ↓ 4 states (or 3 run-lengths)
       ↓ Tribonacci-style recurrence
       ↓ O(n) time, O(1) space

5.  Count good digit strings, positional rules  (LC 1922, note 3)
       ↓ choices INDEPENDENT
       ↓ Multiplication Principle Pattern
       ↓ none
       ↓ product of per-position counts
       ↓ O(log n) time, O(1) space

6.  Decode Ways  (LC 91)
       ↓ 1-digit or 2-digit decision
       ↓ Split-by-Last-Decision Pattern
       ↓ two variables
       ↓ dp[i] = dp[i-1]·valid1 + dp[i-2]·valid2
       ↓ O(n) time, O(1) space

7.  Student Attendance Record II  (LC 552)
       ↓ multiple adjacency constraints
       ↓ Multi-State DP Pattern
       ↓ 6 states (absences x trailing lates)
       ↓ state machine + modulo
       ↓ O(n) or O(log n) via matrix

8.  Count Vowels Permutation  (LC 1220)
       ↓ transition rules between letters
       ↓ State-Machine DP Pattern
       ↓ 5 states
       ↓ dp[i][v] from allowed predecessors
       ↓ O(n) or O(log n) via matrix

9.  Best Time to Buy/Sell with Cooldown  (LC 309)
       ↓ cooldown = adjacency constraint
       ↓ Multi-State DP Pattern
       ↓ 3 states (hold, sold, rest)
       ↓ state transitions per day
       ↓ O(n) time, O(1) space

10. Non-negative Integers without Consecutive Ones  (LC 600)
       ↓ this problem PLUS an upper bound
       ↓ Digit DP Pattern
       ↓ Fibonacci table + bit scan
       ↓ count by bit position, handle "tight"
       ↓ O(log n) time, O(log n) space

11. Fibonacci for n = 10^18
       ↓ linear recurrence, huge index
       ↓ Matrix Exponentiation Pattern
       ↓ 2x2 matrix
       ↓ [[1,1],[1,0]]^n
       ↓ O(log n) time, O(1) space

12. Tiling a 2 x n board with dominoes
       ↓ last tile vertical or two horizontal
       ↓ Split-by-Last-Decision Pattern
       ↓ two variables
       ↓ f(n) = f(n-1) + f(n-2)
       ↓ O(n) time, O(1) space

13. Count subsets with no two adjacent elements
       ↓ same adjacency rule on a set
       ↓ Include-Exclude DP Pattern
       ↓ two variables
       ↓ f(n) = f(n-1) + f(n-2)
       ↓ O(n) time, O(1) space

14. Paint fence, no three consecutive same colour  (LC 276)
       ↓ looks back two
       ↓ Widened-State DP Pattern
       ↓ same/diff counters
       ↓ same = diff_prev, diff = (same+diff)*(k-1)
       ↓ O(n) time, O(1) space

15. Longest subarray without two adjacent equal
       ↓ "longest" not "count"
       ↓ Same DP, max instead of sum
       ↓ running length
       ↓ extend or reset
       ↓ O(n) time, O(1) space
```

# PHASE 8 — FAANG FOLLOW-UP QUESTIONS

**Q1. "What if `n = 10⁵`?" (the actual constraint)**
The naive recursion is `Θ(φⁿ)` and impossible. Use rolling variables: `O(n)` time, `O(1)`
space, reducing mod `10⁹+7` each step (§23 Version 4). **This is the expected submission.**

**Q2. "Where's the modulo?"**
`F(n) ≈ φⁿ`, so `F(10⁵)` has ~20,900 digits — unrepresentable. The problem requires mod
`10⁹+7`. Reduce at every addition, and accumulate in a `long` because the sum of two reduced
values reaches ~`2×10⁹`, uncomfortably close to `Integer.MAX_VALUE`.

**Q3. "Memoise it."**
§23 Version 2. There are only `n` distinct states, so caching collapses `Θ(φⁿ)` to `O(n)`.
Say the diagnosis out loud: *overlapping subproblems*.

**Q4. "Reduce the space to `O(1)`."**
`dp[i]` reads only `dp[i−1]` and `dp[i−2]`; everything older is dead. Keep two variables and
slide the window. §23 Version 4.

**Q5. "What if `n = 10¹⁸`?"**
Matrix exponentiation (§25): write the recurrence as `[[1,1],[1,0]]` and raise it to the
`(n−1)`-th power by binary exponentiation — `O(log n)`. Emphasise that `matPow` is literally
your `Pow(x,n)` code with `1.0 →` identity matrix and `*` → matrix multiply, because binary
exponentiation only needs **associativity and an identity**.

**Q6. "What if THREE consecutive 1s were banned instead of two?"**
Widen the state to the last **two** characters (or track the current run length of 1s):
`F(n) = F(n−1) + F(n−2) + F(n−3)` — a **Tribonacci** recurrence. Derivation: the string ends in
`0`, `01`, or `011`. This is exactly why the **two-state formulation** (§24) is worth keeping —
the collapsed Fibonacci form gives you no path here.

**Q7. "Generalise to no `k` consecutive 1s."**
`F(n) = F(n−1) + F(n−2) + … + F(n−k)` — a **k-bonacci** recurrence. Compute it in `O(n)` with a
sliding-window sum (keep a running total, add the new term, subtract the one falling out), or
`O(k³ log n)` with a `k×k` matrix power.

**Q8. "What if the alphabet weren't binary?"**
For an alphabet of size `m` with "no two adjacent equal": `F(n) = m · (m−1)^(n−1)` — a closed
form, because every position after the first has exactly `m−1` choices **regardless of what
was chosen**. That independence is what collapses it. Nice contrast with this problem, where
the two branches differ.

**Q9. "Now generate the strings, not just count them."**
That's **backtracking**, not DP: build character by character and prune when the previous
character was `1`. Output size is `F(n) ≈ φⁿ`, so it's inherently exponential — which is
precisely why the original asks only for a count.

**Q10. "What's the exact relationship to Fibonacci?"**
`F(n) = Fib(n+2)` with the 1-indexed convention `Fib(1)=Fib(2)=1` (§26). The strong version of
this answer stresses that you **derived** it and could just as easily derive Tribonacci.

**Q11. "Prove your recurrence is correct."**
Show the case split is **exhaustive** (every string ends in `0` or `1`) and **disjoint** (never
both). Then exhibit the bijections: strings of length `n` ending in `0` ↔ all valid strings of
length `n−1`; strings ending in `1` ↔ all valid strings of length `n−2` (strip the forced
trailing `01`). Both are bijections, so the counts add.

**Q12. "Why is `F(0) = 1` and not `0`?"**
There is exactly **one** string of length 0 — the empty string — and it vacuously satisfies the
constraint. It's the empty product / identity element. Setting `F(0)=0` breaks `F(2)=F(1)+F(0)`
(you'd get 2 instead of 3).

**Q13. "What if `n` could be 0 or negative?"**
`F(0)=1` by the above. Negative `n` is undefined — **ask the interviewer**; you'd either throw
`IllegalArgumentException` or document the precondition. Mentioning it shows boundary
discipline.

**Q14. "Where does `int` break, exactly?"**
`F(44) = 1,836,311,903` fits; `F(45) = 2,971,215,073` exceeds `Integer.MAX_VALUE` and wraps
**silently**. Without a modulus you'd need `long` (good to `F(92)`) or `BigInteger` beyond that.

**Q15. "Count binary strings with no `11` AND no `00`."**
Only **2** such strings exist for any `n ≥ 1`: `0101…` and `1010…`. Once the first character is
fixed, every subsequent one is forced. A great check of whether you derive or pattern-match —
many candidates blurt "Fibonacci" reflexively.

**Q16. "What about a circular string (first and last are adjacent)?"**
Split on the first character. If it's `0`, the rest is a line of length `n−1`. If it's `1`, both
neighbours are forced to `0`, leaving a line of length `n−3`. The result is the **Lucas
numbers** — `L(n) = F(n−1) + F(n−3)` in this indexing. (Same trick as House Robber II.)

**Q17. "Can you do it in `O(1)` with a closed form?"**
Binet's formula: `Fib(n) = (φⁿ − ψⁿ)/√5`. In theory `O(1)`, in practice **unusable** for exact
answers — `double` has 53 bits of mantissa and diverges from the true integer beyond `n ≈ 70`,
and it doesn't compose with modular arithmetic. Mention it, then reject it with reasons.

**Q18. "How would you test this?"**
Brute-force enumerate all `2ⁿ` strings for `n ≤ 20` and count the valid ones; compare with the
DP. Check the known table `2, 3, 5, 8, 13`. Boundary: `n = 0, 1, 44, 45`. Property test:
`F(n) == F(n−1) + F(n−2)` for random `n`. Plus a large-`n` timing test to confirm `O(n)`.

**Q19. "How many 1s does a random valid string have on average?"**
Asymptotically a fraction `(1 − 1/√5)/2 ≈ 0.2764` of positions — related to `1/(φ+2)`. You can
derive it by counting total ones across all valid strings with a second DP. A nice "can you
extend the DP to accumulate a statistic?" question.

**Q20. "Find the k-th valid string in lexicographic order."**
Counting becomes **unranking**. At each position, try `0`: the number of completions is a known
Fibonacci value. If `k` is within it, fix `0`; otherwise subtract and place `1` (forcing the
next to `0`). `O(n)` after precomputing the Fibonacci table.

**Q21. "Can this be parallelised?"**
Not the sequential `O(n)` loop — each step depends on the previous. But **matrix
exponentiation** exposes parallelism: the `2×2` multiplications are independent, and more
importantly `M^a · M^b = M^(a+b)` lets you split the exponent across machines and combine
associatively.

**Q22. "What if the constraint were global, e.g. 'at most `j` ones total'?"**
Add a dimension: `dp[i][j][last]` — position, ones used, last character. `O(n·j)` states. The
method is unchanged; only the state grows. Good illustration of *"the constraint defines the
state."*

**Q23. "Connect this to House Robber."**
`LC 198` has the *identical* constraint (no two adjacent) but asks for a **maximum** rather than
a **count**. The recurrence shape is the same — only the combine operator changes from `+` to
`max`. Same derivation, different semiring. That observation is a strong signal.

**Q24. "Is there a combinatorial formula?"**
Yes: `F(n) = Σₖ C(n−k+1, k)` — choose `k` non-adjacent positions for the 1s (§26). It's the
"shallow diagonals of Pascal's triangle sum to Fibonacci" identity. `O(n)` with factorials, and
a genuinely different derivation.

**Q25. "Where does this appear in the real world?"**
Run-length-limited (RLL) codes in magnetic and optical storage forbid certain bit patterns, and
the channel **capacity** is exactly `log₂φ ≈ 0.694` bits per symbol for this constraint. Also:
Zeckendorf representation, Fibonacci coding, and scheduling problems with cooldown periods.

```text
                  first n-2 chars are any valid string   ->  F(n-2)

        F(n) = F(n-1) + F(n-2)        F(0) = 1     F(1) = 2

        for (int i = 2; i <= n; i++) {
            long cur = (p1 + p2) % MOD;
            p2 = p1;  p1 = cur;
        }
        return (int) p1;

   ⚠ NAIVE RECURSION IS Theta(phi^n) — derivation ONLY, never submit it.
   ⚠ F(45) OVERFLOWS int. Use long. Reduce mod EVERY step.
```

## 10-MINUTE REVISION

**The derivation (narrate this, don't recite the formula)**

```text
   1. Define F(n) = number of valid binary strings of length exactly n.
   2. Look at the LAST character — that's where the constraint lives.
   3. Case A, ends in '0': no constraint triggered. First n-1 chars free. F(n-1)
   4. Case B, ends in '1': the previous char MUST be '0'. The string ends "...01".
                           Only the first n-2 chars are free.              F(n-2)
   5. Exhaustive (ends in 0 or 1) and disjoint (never both) -> ADD.
   6. F(n) = F(n-1) + F(n-2),  F(0)=1 (empty string), F(1)=2 ("0","1")
```

**The two-state model (keep this — it survives follow-ups)**

```text
   end0[i] = end0[i-1] + end1[i-1]      (append 0 to anything)
   end1[i] = end0[i-1]                  (append 1 ONLY after a 0)
   answer  = end0[n] + end1[n]

   i  : 1   2   3   4   5
   end0: 1   2   3   5   8
   end1: 1   1   2   3   5
   tot : 2   3   5   8  13
```

**The optimisation ladder**

| Rung | Time | Space | Use when |
|---|---|---|---|
| Naive recursion | `Θ(φⁿ)` | `O(n)` | Explaining only |
| Memoisation | `O(n)` | `O(n)` | Showing the fix |
| Tabulation | `O(n)` | `O(n)` | Need all values |
| **Rolling variables** | `O(n)` | `O(1)` | **`n ≤ 10⁷` — ship this** |
| Matrix power | `O(log n)` | `O(1)` | `n ≤ 10¹⁸` |

**Overflow and modulus**

```text
   F(44) = 1,836,311,903   fits int
   F(45) = 2,971,215,073   OVERFLOWS int (silently)
   F(92) ~ 7.5e18          last long-safe value

   With MOD = 1e9+7:  sum of two reduced values ~ 2e9  -> use long, cast at end.
   Reduction is legal because (a+b) mod m = ((a mod m)+(b mod m)) mod m.
```

**The fork that decides everything**

```text
   Does the rule for position i mention another position?
        NO  -> MULTIPLICATION PRINCIPLE (note 3: Count Good Numbers)

```

**Generalisations to have ready**

```text

       pure recomputation. Memoising gives O(n) time and O(n) space."

   4. "And dp[i] only reads dp[i-1] and dp[i-2], so I don't need the array:

   5. "The answer grows like phi^n — about 20,000 digits at n = 10^5 —

       about 2e9, too close to Integer.MAX_VALUE for comfort."
```

> recurrence: rather than guessing, I'll split by the **last character**, because that's where
> the constraint lives. If the string ends in `0`, nothing is violated and the first `n−1`
> characters can be any valid string — `F(n−1)`. If it ends in `1`, the no-`11` rule forces the
> previous character to be `0`, so the string ends `…01` and only `n−2` characters are free —
> `F(n−2)`. Those cases are exhaustive and disjoint, so I add: `F(n) = F(n−1) + F(n−2)`, with
> `F(0)=1` for the empty string and `F(1)=2`. Let me verify on `n=3`..."*

## Whiteboard explanation tips

```text
   1. WRITE THE CONSTRAINT FIRST, boxed:
           n <= 10^5      answer mod 1e9+7
      Then say what it implies. This frames everything.

   2. ENUMERATE n=3 OR n=4 BY HAND and GROUP BY LAST CHARACTER:

           ENDING IN 0        ENDING IN 1
           0000               0001
           0010               0101
           0100               1001
           1000
           1010
             5 = F(3)           3 = F(2)

      This makes the recurrence self-evident before you write it.

   3. DRAW THE FORCED PAIR:

           ? ? ? ? 1
           ? ? ? 0 1     <- the 1 DRAGS a 0 with it
           \_____/
            free = n-2

   4. DRAW THE 2-STATE MACHINE:

                 +--0--+
                 |     v
             [END0] <--0-- [END1]
                 |            ^
                 +-----1------+
                 (no 1-arrow out of END1 — THAT'S the whole problem)

   5. WRITE THE LADDER in the corner and tick rungs as you climb:
           naive Theta(phi^n) -> memo O(n) -> rolling O(1) -> matrix O(log n)

   6. KEEP A VERIFICATION ROW:
           n : 0  1  2  3  4  5
           F : 1  2  3  5  8 13
      Point at it after writing the code.

   7. WHEN ASKED "three consecutive?", immediately write:
           endings: 0 | 01 | 011  ->  F(n-1)+F(n-2)+F(n-3)
      Five seconds, and it proves the derivation was real.
```

## Formulas & values cheat sheet

```text
   RECURRENCE
        F(n) = F(n-1) + F(n-2)
        F(0) = 1    (the empty string)
        F(1) = 2    ("0" and "1")

        F(n) = Fib(n + 2)        [1-indexed: Fib = 1,1,2,3,5,8,...]

   TWO-STATE FORM
        end0[i] = end0[i-1] + end1[i-1]
        end1[i] = end0[i-1]
        F(n)    = end0[n] + end1[n]

   COMBINATORIAL FORM
        F(n) = SUM over k of C(n-k+1, k)

   GENERALISATIONS
        no 3 consecutive 1s : F(n-1)+F(n-2)+F(n-3)        (Tribonacci)
        no k consecutive 1s : sum of the previous k terms  (k-bonacci)
        alphabet m, no two adjacent equal : m·(m-1)^(n-1)  (closed form)
        no 11 AND no 00     : exactly 2   (for n >= 1)
        circular            : Lucas numbers

   OVERFLOW BOUNDARIES
        F(44) = 1,836,311,903          last int-safe
        F(45) = 2,971,215,073          OVERFLOWS int
        F(92) ~ 7.5e18                 last long-safe

   GROWTH
        F(n) ~ phi^(n+2)/sqrt(5),  phi = 1.6180339887...
        digits ~ 0.209 * n     ->  F(10^5) has ~20,900 digits

   MODULUS
        MOD = 1_000_000_007   (prime, < 2^31, MOD^2 < Long.MAX)
        (a + b) mod m = ((a mod m) + (b mod m)) mod m
        sum of two reduced values ~ 2e9  ->  USE long
```

## The one-line recall (upgraded)

```text
Split by the LAST character: ends in 0 -> F(n-1); ends in 1 -> the previous char
is FORCED to 0 so only n-2 are free -> F(n-2). Exhaustive + disjoint, so ADD:

```

## Final takeaway (upgraded)

```text

   1. DERIVE, DON'T RECOGNISE
      "It's Fibonacci" is worth nothing if you can't say WHY. Split the
      solution set by the LAST decision, check the cases are exhaustive
      and disjoint, ask what smaller version of the SAME problem remains,
      and add. That method survives every follow-up — recognition does not.
      And if you ever catch yourself manipulating concrete numbers like

   2. THE CONSTRAINT DEFINES THE STATE — AND THE CONSTRAINT ON n

      "No two consecutive 1s" looks back exactly one character, so the
      state is one character. And "n <= 10^5, mod 1e9+7" told you the
      required complexity before you understood the problem. Read the
      constraints FIRST; they are the biggest hint in the question.

   3. CLIMB THE LADDER OUT LOUD
```

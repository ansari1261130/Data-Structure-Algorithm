# Recursion Revision Note — Consecutive 1's Not Allowed

Question: [Consecutive 1s Not Allowed](https://www.geeksforgeeks.org/problems/consecutive-1s-not-allowed1912/1)

Pattern: Choices → Cases → Smaller Same Problem

## 1) Core idea

Given an integer `n`, count the number of binary strings of length `n` such that no two consecutive characters are `1`.

Examples:

- `n = 1` → `0`, `1` → answer = 2
- `n = 2` → `00`, `01`, `10` → answer = 3
- `n = 3` → `000`, `001`, `010`, `100`, `101` → answer = 5

The restriction is:

```text
"11" is not allowed
```

That means the next choice depends on the previous digit.

---

## 2) First observation

The restriction is not independent at each position.

If the previous digit is:

- `0` → we may add `0` or `1`
- `1` → we may add only `0`

This is the key insight.

The next choice depends on the previous one, so we need a recurrence.

---

## 3) My initial thinking

For `n = 3`, valid strings are:

```text
000
001
010
100
101
```

We can group them by ending digit:

- ending in `0` → 3 strings
- ending in `1` → 2 strings

Going to `n = 4`:

- strings ending in `0` → `3 × 2 = 6`
- strings ending in `1` → `2 × 1 = 2`

Then total = `6 + 2 = 8`.

This is correct for the example, but it can mislead me if I keep thinking in concrete numbers.

The problem is not the arithmetic itself; it is the fact that `6` and `2` are just values for one example.

I should ask:

```text
What do these numbers represent?
Can I write them in terms of the same function with a smaller input?
```

---

## 4) Warning sign

If I am using values like:

```text
6 × 2 + 2 × 1
```

I should stop and ask:

```text
What is 6?
What is 2?
Can I express these as smaller versions of the same problem?
```

This is a sign that I am solving one specific example instead of the general problem.

---

## 5) Generalization test

Instead of asking only about `n = 5`, ask:

```text
How do I solve for any n?
```

Define:

```text
F(n) = number of valid binary strings of length n
```

Now split all valid strings into two cases:

- ends in `0`
- ends in `1`

---

## 6) Case 1: string ends in 0

If the final character is `0`, then the first `n-1` positions can be any valid string of length `n-1`.

So:

```text
Number of strings ending in 0 = F(n - 1)
```

---

## 7) Case 2: string ends in 1

If the final character is `1`, then the previous character must be `0` because `11` is not allowed.

So the string must end as:

```text
... 0 1
```

Then the first `n-2` positions can be any valid string of length `n-2`.

So:

```text
Number of strings ending in 1 = F(n - 2)
```

---

## 8) Combine the two cases

Every valid string must end in either `0` or `1`.

Therefore:

```text
F(n) = F(n - 1) + F(n - 2)
```

This recurrence came from the choices and the smaller subproblems.

It was not guessed from Fibonacci; it was derived from the logical cases.

---

## 9) Base cases

For `n = 0`:

There is exactly one empty string:

```text
""
```

So:

```text
F(0) = 1
```

For `n = 1`:

Valid strings are:

```text
0
1
```

So:

```text
F(1) = 2
```

Final base cases:

```text
F(0) = 1
F(1) = 2
```

---

## 10) Recursion form

This recurrence directly becomes:

```java
countStrings(n)
    = countStrings(n - 1) + countStrings(n - 2)
```

with base cases:

```java
if (n == 0) return 1;
if (n == 1) return 2;
```

---

## 11) Final Java code

```java
class Solution {
    int countStrings(int n) {
        if (n == 0) return 1;
        if (n == 1) return 2;

        return countStrings(n - 1)
             + countStrings(n - 2);
    }
}
```

---

## 12) Code understanding

Base case:

```java
if (n == 0) return 1;
```

There is exactly one empty string.

Second base case:

```java
if (n == 1) return 2;
```

Valid strings are:

```text
0
1
```

Recursive step:

```java
return countStrings(n - 1) + countStrings(n - 2);
```

This means:

- strings ending in `0` → `F(n-1)`
- strings ending in `1` → `F(n-2)`

Therefore:

```text
F(n) = F(n - 1) + F(n - 2)
```

---

## 13) Recursion tree

For `F(5)`, the tree looks like:

```text
            F(5)
           /    \
        F(4)    F(3)
       /   \    /   \
     F(3) F(2) F(2) F(1)
      / \
   F(2) F(1)
```

Notice that the same values are recomputed many times.

This is why this naive recursion is inefficient.

---

## 14) Important recursion pattern

The pattern is:

```text
CHOICES
  ↓
SPLIT INTO CASES
  ↓
SEE WHAT REMAINS
  ↓
CHECK IF IT IS THE SAME PROBLEM
  ↓
RECURSE
```

For this problem:

- choice = last digit
- if last digit is `0`, we need `F(n-1)`
- if last digit is `1`, previous digit must be `0`, so we need `F(n-2)`

This is the real transferable pattern.

## 16) Generalization test

Whenever I derive a formula, I ask:

```text
Will this work for any n?
```

If I have a value like:

```text
6 × 2 + 2 × 1
```

I should not keep it as a final answer.

I should replace it with meanings:

- `6` = valid strings of length 4 ending in 0
- `2` = valid strings of length 4 ending in 1

Then those become:

```text
F(n - 1)
F(n - 2)
```

and the final form is:

```text
F(n) = F(n - 1) + F(n - 2)
```

---

## 17) Most important lesson

Do not first try to recognize:

```text
This is Fibonacci.
```

Instead, ask:

```text
What choices do I have?
After each choice, what smaller version of the same problem remains?
```

The transferable skill is:

```text
CHOICES → CASES → WHAT REMAINS? → SAME SMALLER PROBLEM? → RECURSION
```

---

## 18) Complexity

This recursive version recomputes the same states repeatedly.

So:

```text
Time Complexity = O(2^n)
```

The recursion depth is at most `n`.

So:

```text
Space Complexity = O(n)
```

---

## 19) Future optimization

Because values like `F(3)`, `F(2)`, `F(1)` are repeated, the next optimization is obvious:

```text
Memoization
```

and later:

```text
Bottom-up DP
```

For now, the goal is to understand how the recurrence is derived, not just to optimize it.

## 20) Recursion checklist

For future problems, ask:

1. What is the current state?
2. What choices do I have?
3. What happens after each choice?
4. What information does the next call need?
5. Can I reduce the problem to the same function with a smaller input?
6. What is the base case?
7. Am I computing the same state repeatedly?

For this problem:

```text
State: F(n)
Choices: last digit is 0 or 1
If last digit = 0 -> F(n-1)
If last digit = 1 -> previous must be 0 -> F(n-2)
Base cases: F(0) = 1, F(1) = 2
```

Final recurrence:

```text
F(n) = F(n-1) + F(n-2)
```

The most important lesson I learned from this problem is:

```text
I do not need to magically see the recurrence.
I need to go one level deeper.
```

If I get something like:

```text

```

I should ask:

```text

What do they represent?

```

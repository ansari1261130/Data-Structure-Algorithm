# Recursion Revision Note — Pow(x, n)

Question: [Pow(x, n)](https://leetcode.com/problems/powx-n/)

Pattern: Reduce-by-Half / Binary Exponentiation

## 1) Core idea

Calculate `x^n` efficiently.

Examples:

- `2^3 = 8`
- `2^-3 = 0.125`
- `2.1^3 = 9.261`

The main challenge is to make recursion move toward the base case and reduce work quickly.

---

## 2) First thought — simple recursion

```java
pow(x, n) = x * pow(x, n - 1)
```

Base case:

```java
if (n == 0) return 1;
```

Example:

```text
pow(2.1, 3)
= 2.1 * pow(2.1, 2)
= 2.1 * 2.1 * pow(2.1, 1)
= 2.1 * 2.1 * 2.1 * pow(2.1, 0)
= 9.261
```

This works, but it is too slow for large `n`.

---

## 3) Problem with negative n

If we do:

```java
pow(x, n - 1)
```

then for negative `n` we move away from zero:

```text
-3 -> -4 -> -5 -> ...
```

This never reaches the base case.

Important rule:

A recursive state must move toward the base case.

For negative powers:

```text
x^(-n) = 1 / x^n
```

Example:

```text
2^-3 = 1 / 2^3 = 1 / 8 = 0.125
```

---

## 4) First attempt for negative n

One idea is:

```java
n < 0 -> return (1 / x) * pow(x, n + 1)
```

This moves toward `0`:

```text
-3 -> -2 -> -1 -> 0
```

Example:

```text
pow(2, -3)
= (1/2) * pow(2, -2)
= (1/2) * (1/2) * pow(2, -1)
= (1/2) * (1/2) * (1/2) * pow(2, 0)
= 1/8 = 0.125
```

This is mathematically correct, but still too slow.

---

## 5) Why O(n) is too slow

With:

```java
n -> n - 1
```

for `n = 1,000,000,000`, the recursion depth is huge.

So the time complexity is:

```text
O(n)
```

This is not acceptable.

---

## 6) Key optimization — reduce n by half

Instead of reducing by 1, reduce by half:

```java
n -> n / 2
```

Use the identity:

```text
x^8 = x^4 * x^4
```

and in general:

```text
x^n = x^(n/2) * x^(n/2)
```

Therefore we can do:

```java
half = pow(x, n / 2);
return half * half;
```

This reduces recursion depth to:

```text
O(log n)
```

---

## 7) Even exponent case

For even `n`:

```text
x^n = x^(n/2) * x^(n/2)
```

So:

```java
half = pow(x, n / 2);
return half * half;
```

Example:

```text
pow(2, 8)
half = pow(2, 4) = 16
return 16 * 16 = 256
```

---

## 8) Odd exponent case

For odd `n`:

```text
x^5 = x * x^4
```

and since:

```text
x^4 = x^2 * x^2
```

we get:

```text
x^5 = x * x^2 * x^2
```

So:

```java
half = pow(x, n / 2);
return x * half * half;
```

Example:

```text
pow(2, 5)
half = pow(2, 2) = 4
return 2 * 4 * 4 = 32
```

---

## 9) Important observation about `half`

Every recursive call has its own local variables.

So:

```java
double half = pow(x, n / 2);
```

in one call does not overwrite the value in another call.

Example:

```text
pow(2, 8)   -> half = 16
pow(2, 4)   -> half = 4
pow(2, 2)   -> half = 2
pow(2, 1)   -> half = 1
pow(2, 0)   -> base case
```

The value from the deeper call returns upward through the recursion stack.

---

## 10) Negative exponent + optimization

We know:

```text
x^(-n) = (1 / x)^n
```

So instead of a separate negative recursion style, we transform first:

```java
if (N < 0) {
    x = 1 / x;
    N = -N;
}
```

Then we apply the same positive-exponent recursion.

---

## 11) Integer.MIN_VALUE problem

Java `int` cannot store:

```text
2147483648
```

So for `n = Integer.MIN_VALUE`, doing:

```java
n = -n;
```

overflows.

This is why we use:

```java
long N = n;
```

Then:

```java
N = -N;
```

is safe.

---

## 12) Final recursive structure

Base case:

```java
if (n == 0) return 1;
```

Recursive step:

```java
half = pow(x, n / 2);
result = half * half;

if (n % 2 != 0) {
    result = x * result;
}

return result;
```

This is the divide-and-conquer binary exponentiation pattern.

---

## 13) Final Java code

```java
class Solution {
    public double myPow(double x, int n) {
        long N = n;

        if (N < 0) {
            x = 1 / x;
            N = -N;
        }

        return power(x, N);
    }

    private double power(double x, long n) {
        if (n == 0) {
            return 1;
        }

        double half = power(x, n / 2);
        double result = half * half;

        if (n % 2 != 0) {
            result = x * result;
        }

        return result;
    }
}
```

---

## 14) Recursion trace

Example: `myPow(2, 8)`

```text
power(2, 8)
  -> power(2, 4)
      -> power(2, 2)
          -> power(2, 1)
              -> power(2, 0) -> 1

power(2, 1): half = 1, result = 2
power(2, 2): half = 2, result = 4
power(2, 4): half = 4, result = 16
power(2, 8): half = 16, result = 256
```

Final answer:

```text
2^8 = 256
```

---

## 15) What does `power(x, n)` mean?

It means:

> Calculate `x` raised to the power `n`.

The helper only needs:

- `x`
- `n`

and returns:

```text
x^n
```

---

## 16) Recursion pattern identified

This problem uses:

```text
Reduce by Half / Divide and Conquer
```

State:

```text
n
```

It shrinks like this:

```text
n -> n / 2 -> n / 4 -> ... -> 0
```

Then the returned values are combined:

- even: `half * half`
- odd: `x * half * half`

---

## 17) Complexity

At each recursive call, `n` becomes half.

So:

```text
Time Complexity = O(log |n|)
Space Complexity = O(log |n|)
```

This is much better than the simple `O(n)` recursion.

---

## 18) Important lessons

### Lesson 1

A recursive state must move toward the base case.

### Lesson 2

A recursive solution is not automatically efficient.

### Lesson 3

Look for mathematical relationships that reduce the problem faster.

### Lesson 4

Use divide-and-conquer when the problem has a repeated structure.

### Lesson 5

Be careful about overflow when using `int`.

---

## 19) Common mistakes

1. Using `n - 1` without noticing negative exponent problem
2. Never checking whether recursion moves toward base case
3. Forgetting to handle `n < 0`
4. Ignoring `Integer.MIN_VALUE` overflow
5. Not using the half-power optimization

---

## 20) One-line recall

```text
Negative n -> flip x and make n positive; n == 0 -> 1; half = pow(x, n/2); even -> half*half; odd -> x*half*half; use long for n
```

---

## 21) Final takeaway

Do not memorize only the code.

Remember the reasoning:

1. The first version is too slow.
2. We need to shrink `n` faster.
3. Use `n / 2`.
4. Use the identity for powers.
5. Handle negative and overflow cases first.
6. Combine the recursive result correctly.

This is the real concept to remember.

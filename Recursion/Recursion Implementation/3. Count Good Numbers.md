# Recursion Revision Note — Count Good Numbers

Question: [Count Good Numbers](https://leetcode.com/problems/count-good-numbers/)

Pattern: Counting + Fast Exponentiation

## 1) Core idea

A digit string is called good if:

- even indices must be even digits
- odd indices must be prime digits

Indices are 0-based.

Even digits:

- 0, 2, 4, 6, 8
- choices = 5

Prime digits:

- 2, 3, 5, 7
- choices = 4

So each position is independent.

Instead of generating strings, count the number of valid choices per position.

---

## 2) First observation

For every even index:

- 5 choices

For every odd index:

- 4 choices

So the total number of valid strings is:

```text
5 × 5 × 5 × ... (for even positions)
×
4 × 4 × 4 × ... (for odd positions)
```

Example: `n = 1`

- index 0 is even
- choices = 5

Answer = 5

---

## 3) Example: n = 2

Indices: 0 1

- 0 is even
- 1 is odd

Choices:

```text
5 × 4 = 20
```

So answer = 20.

This matches the pattern:

```text
n = 1 → 5
n = 2 → 5 × 4 = 20
n = 3 → 5 × 4 × 5 = 100
n = 4 → 5 × 4 × 5 × 4 = 400
```

---

## 4) Important pattern

The choices alternate:

```text
E O E O E O ...
```

So the pattern is:

```text
5, 4, 5, 4, 5, 4, ...
```

For `n = 6`, the total is:

```text
5 × 4 × 5 × 4 × 5 × 4
```

---

## 5) Count even and odd positions

We need to know:

- how many even indices exist
- how many odd indices exist

Examples:

- `n = 1` → even = 1, odd = 0
- `n = 2` → even = 1, odd = 1
- `n = 3` → even = 2, odd = 1
- `n = 4` → even = 2, odd = 2
- `n = 5` → even = 3, odd = 2

Pattern:

```text
odd = n / 2
even = n - odd
```

Because Java integer division gives floor(n / 2).

---

## 6) General formula

Each even index contributes 5 choices.
Each odd index contributes 4 choices.

So the answer is:

```text
answer = 5^even × 4^odd
```

where:

```text
odd = n / 2
even = n - odd
```

Final formula:

```text
answer = 5^(n - n/2) × 4^(n/2)
```

Example: `n = 5`

```text
odd = 5 / 2 = 2
even = 5 - 2 = 3

answer = 5^3 × 4^2 = 125 × 16 = 2000
```

---

## 7) Why we cannot use Math.pow()

For large `n`, values like `5^even` and `4^odd` can become enormous.

The problem requires answer modulo `10^9 + 7`.

So we need modular exponentiation, also called fast power / binary exponentiation.

---

## 8) Connection with Pow(x, n)

The previous problem taught us:

```text
x^n
```

can be calculated efficiently by dividing `n` by 2.

Instead of:

```text
n -> n - 1
```

we use:

```text
n -> n / 2
```

This is the same idea as:

```text
x^8 = x^4 × x^4
```

and recursively:

```text
x^n = x^(n/2) × x^(n/2)
```

So recursion depth becomes:

```text
O(log n)
```

This is exactly the pattern we reuse here.

---

## 9) Fast power — even exponent

For even exponent:

```text
x^8 = x^4 × x^4
```

So if `n` is even:

```java
half = power(x, n / 2);
return half * half;
```

---

## 10) Fast power — odd exponent

For odd exponent:

```text
x^5 = x × x^4
```

and since:

```text
x^4 = x^2 × x^2
```

we get:

```text
x^5 = x × x^2 × x^2
```

So for odd `n`:

```java
half = power(x, n / 2);
return x * half * half;
```

---

## 11) Modulo handling

The problem requires:

```text
answer % MOD
```

where:

```text
MOD = 1,000,000,007
```

We must apply modulo during recursive multiplication, not only at the end.

This is valid because:

```text
(a × b) % MOD = ((a % MOD) × (b % MOD)) % MOD
```

So we do:

```java
long res = (half * half) % MOD;
```

and for odd cases:

```java
return (int)((x * res) % MOD);
```

---

## 12) Java overflow issue

Even if both values are less than `MOD`, their product can still be large.

Example:

```text
a × b
```

can become around `10^18`, which is far greater than `int` max.

So we must use `long` before modulo.

```java
(long) a * b
```

Then apply modulo.

---

## 13) First version of my solution

I first wrote:

```java
return (int) pow(5, even) * pow(4, odd);
```

This had a bug because the multiplication could overflow before the final answer was computed.

Correct version:

```java
(long) pow(5, even) * pow(4, odd) % MOD
```

Also, inside `pow()`, repeated multiplication must stay modulo-safe.

---

## 14) Final solution

```java
class Solution {
    int MOD = 1_000_000_007;

    public int countGoodNumbers(long n) {
        long odd = n / 2;
        long even = n - odd;

        return (int)((long) pow(5, even) * pow(4, odd) % MOD);
    }

    private int pow(int x, long n) {
        if (n == 0) {
            return 1;
        }

        long half = pow(x, n / 2);
        long res = (half * half) % MOD;

        if (n % 2 != 0) {
            return (int)((x * res) % MOD);
        }

        return (int) res;
    }
}
```

## 15) Recursion trace

Example: `pow(2, 8)`

```text
pow(2, 8)
  ↓
pow(2, 4)
  ↓
pow(2, 2)
  ↓
pow(2, 1)
  ↓
pow(2, 0)
```

Base case:

```text
pow(2, 0) -> 1
```

Return upward:

```text
pow(2, 1): half = 1, result = 2
pow(2, 2): half = 2, result = 4
pow(2, 4): half = 4, result = 16
pow(2, 8): half = 16, result = 256
```

## 16) What does pow(x, n) mean?

The helper function:

```java
pow(x, n)
```

means:

```text
Calculate x^n modulo MOD.
```

The helper does not care whether `x` is 5 or 4; it only computes the power efficiently.

---

## 17) Why this is not a string generation problem

At first, the problem talks about digit strings, which may make us think of generating all strings and checking them.

That is impossible for large `n`.

For example:

- `n = 4` → `10^4` strings
- `n = 50` → `10^50` strings

We should not generate strings.

The correct idea is:

- each position has independent choices
- count choices directly
- multiply them

This converts the problem from string generation to counting + mathematics.

---

## 18) Why multiplication works

If one position has A choices and another has B choices, then total possibilities are:

```text
A × B
```

This is the multiplication principle.

So:

```text
5^even × 4^odd
```

is valid because each position contributes independently.

---

## 19) Complexity

We calculate huge powers using fast exponentiation, so:

```text
Time Complexity = O(log n)
Space Complexity = O(log n)
```

No strings are generated and no arrays are required.

## 20) Recursion pattern identified

This problem combines two ideas:

### Pattern 1: Counting / Combinatorics

Each position independently contributes a fixed number of choices.

So:

```text
total = product of choices
```

### Pattern 2: Divide by 2 Recursion

Large powers are computed by:

```text
n -> n / 2
```

This is the classic:

- fast exponentiation
- binary exponentiation
- exponentiation by squaring

---

## 21) Important recursion lessons

### Lesson 1

Before writing recursion, look for mathematical structure.

Here:

- even index → 5 choices
- odd index → 4 choices

### Lesson 2

Do not generate objects when only the count is required.

### Lesson 3

If the same operation repeats many times, ask whether it can be reduced faster.

### Lesson 4

Modulo is not only an end-step; apply it during multiplication when values are large.

### Lesson 5

Watch data types carefully.

Even if `a < MOD` and `b < MOD`, their product may still overflow `int`.

Use `long` before applying modulo.

## 24) Common mistakes

1. Generating all strings instead of counting choices
2. Forgetting the pattern of even and odd positions
3. Missing modulo handling for large powers
4. Forgetting to use `long` during multiplication
5. Applying modulo only at the very end instead of during recursion

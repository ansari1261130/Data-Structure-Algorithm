# Recursion Revision Note — Generate Parentheses

Question: [Generate Parentheses](https://leetcode.com/problems/generate-parentheses/description/)

Pattern: Backtracking / Constraint-Based Recursion

## 1) Core idea

We are given `n` pairs of parentheses and need to generate all valid combinations.

A valid string must satisfy:

- every opening bracket must have a matching closing bracket
- at every point in the string, number of closing brackets must not exceed number of opening brackets
- total open count must be `n`
- total close count must be `n`

So the problem is not about building all strings blindly.

It is about building only valid strings using constraints.

---

## 2) Why brute force is not enough

A naive approach would generate all strings of length `2n` and then check validity.

For `n = 8`, that is already huge.

Instead, we build only valid strings.

We decide at each step:

- can I add `'('`?
- can I add `')'`?

and only proceed if the choice keeps the string valid.

---

## 3) Key state to track

At every recursive call, store:

- current string built so far
- number of open brackets used
- number of close brackets used

If we track this, we can apply rules locally.

The decisions are:

```text
if open < n -> add '('
if close < open -> add ')'
```

This directly enforces validity.

---

## 4) Important constraint

The central rule is:

```text
closeCount <= openCount
```

Why?

Because if the number of closing brackets becomes greater than the number of opening brackets, the string becomes invalid.

Example:

```text
())
```

At some point we had more `)` than `(`, which is not allowed in a valid prefix.

So when building the string, we must reject that branch immediately.

---

## 5) Base case

A recursive branch is complete when:

```text
open == n and close == n
```

At that moment, we have built a valid balanced string.

We add it to the answer list.

---

## 6) Recursion structure

At each step:

```java
if (open < n) {
    choose '(';
    recurse;
}

if (close < open) {
    choose ')';
    recurse;
}
```

This is the whole idea.

We do not generate all strings first.

We generate only strings that still can become valid.

---

## 7) Example: n = 3

Start with empty string.

Case 1: add `(`

```text
(
```

Then maybe add `(` again, then `(` again, then close etc.

Possible valid outputs:

```text
((()))
(()())
(())()
()(())
()()()
(())()
```

More precisely, the valid outputs are:

```text
((()))
(()())
(())()
()(())
()()()
```

There are 5 valid combinations for `n = 3`.

---

## 8) Why this works

Every recursive call represents a partial valid prefix.

Then we add only those next brackets that do not violate the rules.

This guarantees:

- prefix remains valid at every step
- final string is balanced
- all valid combinations are reached
- no invalid strings enter the answer

This is exactly the structure of backtracking:

```text
Choose → Check constraint → Recurse → Backtrack
```

---

## 9) Core backtracking pattern

```java
void backtrack(String s, int open, int close) {
    if (open == n && close == n) {
        ans.add(s);
        return;
    }

    if (open < n) {
        backtrack(s + "(", open + 1, close);
    }

    if (close < open) {
        backtrack(s + ")", open, close + 1);
    }
}
```

This matches the exact logic of the problem.

---

## 10) Final Java code

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> ans = new ArrayList<>();
        backtrack(ans, "", 0, 0, n);
        return ans;
    }

    private void backtrack(List<String> ans, String s, int open, int close, int n) {
        if (open == n && close == n) {
            ans.add(s);
            return;
        }

        if (open < n) {
            backtrack(ans, s + "(", open + 1, close, n);
        }

        if (close < open) {
            backtrack(ans, s + ")", open, close + 1, n);
        }
    }
}
```

---

## 11) Why this is called backtracking

At each step, we make a choice.

If the choice leads to a valid prefix, we continue.

If not, we stop exploring that branch.

This is backtracking:

- choose a path
- recurse deeper
- undo choice naturally by returning to caller

No extra cleanup is needed because strings are immutable or built as new ones per recursion step.

---

## 12) Common mistakes

### Mistake 1: allowing more closing brackets than opening brackets

This is the biggest correctness bug.

```java
if (close < open)
```

must be checked before choosing `)`.

### Mistake 2: forgetting the limit on open brackets

We cannot add more than `n` opening brackets.

```java
if (open < n)
```

### Mistake 3: adding closing bracket too early

If `open == 0`, we cannot add `)` because the prefix would be invalid.

### Mistake 4: not stopping at base case

When both counts reach `n`, we must add the result immediately and stop.

### Mistake 5: generating strings and checking later

This is slower and unnecessary.

We should enforce validity while building the string.

## 13) Recursion pattern identified

This problem is a classic pattern:

```text
Choose next bracket
↓
Check if it keeps current prefix valid
↓
Recurse deeper
↓
When all pairs used, store the string
```

The pattern is:

```text
Choose → Check → Recurse → Backtrack
```

This is a standard backtracking template.

---

## 14) Example of valid prefix logic

Suppose current prefix is:

```text
(()
```

Then:

- `open = 2`, `close = 1`, `n = 3`
- we may still add `(` because `open < n`
- we may also add `)` because `close < open`

But if the prefix were:

```text
())
```

then `close = 2`, `open = 1`, and `close < open` is false. So `)` is not allowed.

This is why the recursion naturally respects validity.

## 15) Time complexity

Each valid arrangement corresponds to a leaf in the recursion tree.

The total number of generated valid strings is the Catalan number:

```text
C_n = (1 / (n + 1)) * binomial(2n, n)
```

Thus the time complexity is:

```text
O(C_n)
```

and in practice it is usually described as:

```text
O(4^n / sqrt(n))
```

The recursion depth is at most:

```text
O(n)
```

So the space complexity is:

```text
O(n)
```

for the recursion stack, plus output storage.

---

## 16) Why this is not just a stack problem

It is not a direct stack-pop problem because we are generating all valid strings, not validating an existing one.

The reasoning is:

- maintain balance while building
- prune invalid branches immediately
- stop when both counts reach `n`

This is a recursion + constraints problem, not just a standard stack problem.

## 17) Recursion checklist for future problems

For problems like this, ask:

1. What is the current state?
2. What choices are valid?
3. What constraint must hold before a choice is allowed?
4. What is the smallest subproblem that remains?
5. What is the base case?
6. Can I prune invalid branches early?

For Generate Parentheses:

```text
State: current string + open count + close count
Valid choices: add '(' if open < n; add ')' if close < open
Base case: open == n and close == n
```

## 20) Final takeaway

The real concept is not “how to generate parentheses” in isolation.

The real concept is:

```text
Build only valid prefixes using constraints.
```

This is the reason backtracking works so well here.

When a branch violates the balance rule, we do not explore it further.

That is the heart of the solution.

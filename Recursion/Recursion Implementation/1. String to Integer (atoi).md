# Recursion Revision Note — String to Integer (atoi)

Question: [String to Integer (atoi)](https://leetcode.com/problems/string-to-integer-atoi/)

Pattern: State-Carrying / Top-Down Recursion

## 1) Core idea

Convert a string into a 32-bit signed integer.

Examples:

- "1337c0d3" -> 1337
- "   -1337abc" -> -1337
- "+42" -> 42
- "4193 with words" -> 4193
- "words 987" -> 0

Important: once digit reading starts, stop at the first non-digit.

---

## 2) Problem breakdown

1. Skip leading spaces
2. Handle optional `+` / `-`
3. Read consecutive digits
4. Stop at first non-digit
5. Handle overflow
6. Return the answer

Example:

Input: "   -1337c0d3"

- Skip spaces
- Detect `-`
- Read `1, 3, 3, 7`
- Stop at `c`
- Apply sign
- Result = -1337

---

## 3) Whitespace rule to remember

Leading spaces are skipped before recursion.

After number starts, any non-digit (including space) ends digit reading.

```text
"   1337"  -> skip leading spaces
"1337 abc" -> stop at space after number
```

---

## 4) Why use index instead of substring?

String is immutable, so we should not keep creating smaller substrings.

Use a single string and a moving index instead.

```text
helper(s, 0, 0)
helper(s, 1, 1)
helper(s, 2, 13)
helper(s, 3, 133)
helper(s, 4, 1337)
```

This is the key recursion idea:

A problem does not need a smaller string; it needs a smaller logical state.

---

## 5) Recursive state

```java
helper(s, i, res)
```

Meaning:

> Process the string starting from index `i`, while `res` stores the number built so far.

State meaning:

- `s` -> original string
- `i` -> current index
- `res` -> accumulated number

Example:

```java
helper(s, 3, 133)
```

means: "I am at index 3 and already built 133."

---

## 6) State propagation

```text
"1337c0d3"

helper(s, 0, 0)
 -> helper(s, 1, 1)
 -> helper(s, 2, 13)
 -> helper(s, 3, 133)
 -> helper(s, 4, 1337)
 -> stop at 'c'
 -> return 1337
```

Every call has its own state.

```java
helper(s, i + 1, newRes)
```

does not change the previous call's values.

---

## 7) Convert char to digit

```java
int digit = s.charAt(i) - '0';
```

Because:

```java
'7' - '0' = 7
```

Do not use `- 'a'` for digits.

---

## 8) Base case

Recursion stops when:

- end of string reached
- current char is not a digit

```java
if (i == s.length()
        || s.charAt(i) < '0'
        || s.charAt(i) > '9') {
    return res;
}
```

Very important: base case should return the valid accumulated answer, not always `0`.

---

## 9) Transition step

At every valid digit:

```java
digit = s.charAt(i) - '0';
res = res * 10 + digit;
i = i + 1;
return helper(s, i, res);
```

This is the standard pattern:

```text
current state -> read digit -> update res -> move index -> recurse
```

---

## 10) Sign handling

Do not do:

```java
int res = 0;
if (s.charAt(i) == '-') {
    res = -res;
}
```

Why? Because `-0` is still `0`, so sign information is lost.

Instead:

```java
int sign = 1;

if (s.charAt(i) == '-') {
    sign = -1;
    i++;
}
else if (s.charAt(i) == '+') {
    i++;
}
```

Then build magnitude recursively and do:

```java
result = sign * result;
```

---

## 11) When does sign belong in recursion?

Ask: does this value change during recursion?

- `i` changes -> yes, recursive state
- `res` changes -> yes, recursive state
- `sign` stays fixed -> no, handle outside recursion

---

## 12) Overflow is the dangerous part

Wrong order:

```java
res = res * 10 + digit;
if (res > Integer.MAX_VALUE) return ...;
```

This can overflow before checking.

Correct approach:

```java
if (res > (limit - digit) / 10) {
    return limit;
}
```

This checks safety before creating the next state.

---

## 13) Limits

For 32-bit signed integer:

- `Integer.MAX_VALUE = 2147483647`
- `Integer.MIN_VALUE = -2147483648`

So:

```java
long limit = (sign == -1)
        ? 2147483648L
        : 2147483647L;
```

---

## 14) Final recursion flow

```text
myAtoi(s)
  -> skip spaces
  -> read optional sign
  -> set limit
  -> helper(s, i, 0, limit)
      -> if digit: check overflow, update res, recurse
      -> else: return res
  -> apply sign once
```

---

## 15) Final Java code

```java
class Solution {
    public int myAtoi(String s) {
        int i = 0;

        while (i < s.length() && s.charAt(i) == ' ') {
            i++;
        }

        int sign = 1;

        if (i < s.length() && s.charAt(i) == '-') {
            sign = -1;
            i++;
        } else if (i < s.length() && s.charAt(i) == '+') {
            i++;
        }

        long limit = (sign == -1)
                ? 2147483648L
                : 2147483647L;

        long result = helper(s, i, 0, limit);
        result = sign * result;

        return (int) result;
    }

    private long helper(String s, int i, long res, long limit) {
        if (i == s.length()
                || s.charAt(i) < '0'
                || s.charAt(i) > '9') {
            return res;
        }

        int digit = s.charAt(i) - '0';

        if (res > (limit - digit) / 10) {
            return limit;
        }

        res = res * 10 + digit;
        return helper(s, i + 1, res, limit);
    }
}
```

## 16) Complexity

Time: `O(n)`

Space: `O(n)` because recursion uses stack space.

---

## 17) Must-remember pattern

Pattern:

```text
State-Carrying / Top-Down Recursion
```

Structure:

```text
Current state
  -> check base case
  -> process current element
  -> update state
  -> pass state down
  -> recursive call
```

For this problem:

```java
helper(s, i, res)
```

means:

"Process remaining digits starting from index `i`, while `res` stores the number built so far."

---

## 18) Common mistakes

1. Using substring in every call
2. Returning `0` in base case
3. Using `s.charAt(i) - 'a'`
4. Using `res = -res` when `res` is `0`
5. Handling whitespace inside recursion instead of before it
6. Checking overflow after the overflow has already happened

---

## 19) One-line recall

```text
Skip spaces -> handle sign -> find limit -> recurse with index + accumulated result -> convert digit with '0' -> check overflow before update -> stop at first non-digit -> apply sign once
```

---

## 20) Final takeaway

Do not memorize only the code.

Remember the thought process:

1. What is getting smaller?
2. What information must be carried?
3. What is the base case?
4. What valid value should be returned there?
5. What changes before recursion?
6. Is the next state safe?

This is the real concept to remember.

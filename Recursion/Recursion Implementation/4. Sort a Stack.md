# Recursion Revision Note — Sort a Stack

Question: [Sort a Stack](https://www.geeksforgeeks.org/problems/sort-a-stack/1)

Pattern: Remove → Sort Remaining → Insert

## 1) Core idea

Given a stack, sort it using recursion.

Example:

```text
[3, 32, 2, 11, 41]
```

Assume the top is the rightmost element:

```text
[3, 32, 2, 11, 41]
                 ↑
                TOP
```

Final sorted stack:

```text
[2, 3, 11, 32, 41]
```

The idea is not to use another stack.

Instead, recursion itself becomes the temporary storage.

---

## 2) First thought

The main question is:

```text
How can we sort a stack using only recursion?
```

The solution is:

1. remove one element
2. recursively sort the remaining stack
3. insert the removed element into the correct position

So the two important functions are:

```java
sortStack(stack)
insertElement(stack, element)
```

These are different jobs.

---

## 3) Important observation

We do not need another explicit stack.

We use:

- the same stack
- the Java recursion call stack as temporary memory

Example:

```text
[3, 32, 2, 11, 41]
```

Recursive descent removes elements one by one:

```text
[3, 32, 2, 11]
[3, 32, 2]
[3, 32]
[3]
[]
```

At this point the stack is empty, and the recursion has remembered removed elements through the call stack.

---

## 4) Core recursive idea

The correct pattern is:

```java
sortStack(stack):
    element = pop()
    sortStack(stack)
    insertElement(stack, element)
```

Why this works:

- the smaller stack is sorted first
- then the removed element is placed correctly

This is the main recursion pattern for the problem.

---

## 5) Recursive descent example

```text
stack = [3, 32, 2, 11, 41]
```

We remove one element at a time:

```text
pop 41 -> [3, 32, 2, 11]
pop 11 -> [3, 32, 2]
pop 2  -> [3, 32]
pop 32 -> [3]
pop 3  -> []
```

The stack is empty now, so base case is reached.

---

## 6) Base case

```java
if (st.isEmpty()) {
    return;
}
```

Why?

An empty stack is already sorted.

---

## 7) What happens when recursion returns?

After empty stack is reached, recursion starts returning upward.

Example:

```text
insert 3 -> [3]
insert 32 -> [3, 32]
insert 2 -> [2, 3, 32]
insert 11 -> [2, 3, 11, 32]
insert 41 -> [2, 3, 11, 32, 41]
```

This is where sorting is completed.

---

## 8) What does insertElement() do?

`insertElement(stack, element)` means:

> The stack is already sorted. Insert one element into its proper position.

This is the crucial point.

We are not sorting the whole stack again. We are just inserting one value.

---

## 9) Insertion rule

Suppose:

```text
stack = [3, 32]
element = 2
```

Top is 32.

Because:

```text
32 > 2
```

we cannot simply push 2.

So we pop the larger blocker:

```text
[3]
```

Then pop 3 again:

```text
[]
```

Now we can push 2:

```text
[2]
```

Then restore 3 and 32:

```text
[2, 3, 32]
```

This is the heart of the insertion logic.

---

## 10) Key recursive pattern inside insertion

The insertion function follows:

```java
int remove = st.pop();
insertElement(st, element);
st.push(remove);
```

This is a classic pattern:

- remove blocker
- solve smaller insertion problem
- restore blocker

---

## 11) When can we push directly?

We push the element immediately when:

```java
st.isEmpty() || st.peek() < element
```

Then:

```java
st.push(element);
return;
```

Example:

```text
stack = [2, 3, 32]
element = 41
```

Since `32 < 41`, 41 belongs on top.

So we just push it.

---

## 12) When do we pop?

If:

```java
st.peek() > element
```

then the top element blocks the correct place.

We remove it and recurse.

This is the exact idea that allows insertion without a second stack.

---

## 13) Why not use a loop?

A loop could also find the correct place, but this problem is about recursion.

The recursive version replaces:

```java
while (top > element) pop();
```

with:

```java
if (top > element) {
    remove = pop();
    insertElement(...);
    push(remove);
}
```

This is the recursive equivalent of the loop.

---

## 14) Why insertElement() does not call sortStack()

This is an important distinction:

- `sortStack()` sorts the whole remaining stack
- `insertElement()` inserts only one element into an already sorted stack

So the correct flow is:

```java
sortStack(st);
insertElement(st, element);
```

not:

```java
insertElement(st, element); // wrong idea
sortStack(st);
```

Because at that point the stack is already sorted.

---

## 15) Complete flow

For:

```text
[3, 32, 2, 11, 41]
```

The full sequence is:

```text
sort([3, 32, 2, 11, 41])
  -> pop 41
  -> sort([3, 32, 2, 11])
      -> pop 11
      -> sort([3, 32, 2])
          -> pop 2
          -> sort([3, 32])
              -> pop 32
              -> sort([3])
                  -> pop 3
                  -> sort([])
                  -> insert 3
              -> insert 32
          -> insert 2
      -> insert 11
  -> insert 41
```

Final result:

```text
[2, 3, 11, 32, 41]
```

---

## 16) Final Java code

```java
class Solution {

    public void sortStack(Stack<Integer> st) {
        if (st.isEmpty()) {
            return;
        }

        int element = st.pop();

        sortStack(st);

        insertElement(st, element);
    }

    private void insertElement(Stack<Integer> st, int element) {
        if (st.isEmpty() || st.peek() < element) {
            st.push(element);
            return;
        }

        int remove = st.pop();

        insertElement(st, element);

        st.push(remove);
    }
}
```

---

## 17) Explanation of sortStack()

```java
public void sortStack(Stack<Integer> st)
```

This function sorts the entire stack.

Flow:

```java
if (st.isEmpty()) return;

int element = st.pop();
sortStack(st);
insertElement(st, element);
```

This is remembered as:

```text
POP → SORT → INSERT
```

---

## 18) Explanation of insertElement()

```java
private void insertElement(Stack<Integer> st, int element)
```

This function assumes the stack is already sorted.

Flow:

```java
if (st.isEmpty() || st.peek() < element) {
    st.push(element);
    return;
}

int remove = st.pop();
insertElement(st, element);
st.push(remove);
```

This is remembered as:

```text
POP → RECURSE → RESTORE
```

---

## 19) Important variable: remove

When a blocking element is popped, we store it in a local variable:

```java
int remove = st.pop();
```

This value is not lost.

After recursion finishes, we restore it with:

```java
st.push(remove);
```

This ensures the stack structure is preserved while the smaller insertion problem is solved.

---

## 20) Why the same stack works

No second stack is needed.

The same stack is modified temporarily and then restored.

Example:

```text
[3, 32]
```

We do:

```text
pop 32 -> [3]
pop 3 -> []
push 2 -> [2]
push 3 -> [2, 3]
push 32 -> [2, 3, 32]
```

The recursion call stack remembers the removed elements while the smaller problem is solved.

---

## 21) Important recursion concept

This problem demonstrates:

```text
Solve the smaller problem first, then use the result to solve the original problem.
```

For `sortStack()`:

- sort smaller stack
- insert removed element

For `insertElement()`:

- remove blocker
- solve smaller insertion problem
- restore blocker

This is recursion through reduction + restoration.

---

## 22) Common confusions

### Confusion 1: Do I need another stack?

No. The recursion call stack itself temporarily stores removed values.

### Confusion 2: Should I pop everything first?

Yes, recursively sort the remaining stack by popping until empty, then insert back.

### Confusion 3: Are we just pushing back everything?

No. Every element is inserted into its correct position.

### Confusion 4: Why do we pop and restore again?

The top element may block the correct insertion position. We remove it, solve the smaller problem, then restore it.

### Confusion 5: Should insertElement call sortStack?

No. The stack is already sorted at that stage.

---

## 23) Recursion pattern identified

This problem has two recursive patterns:

### Pattern 1

```text
Remove one
↓
Solve remaining problem
↓
Insert removed item
```

### Pattern 2

```text
Remove blocker
↓
Solve smaller insertion problem
↓
Restore blocker
```

This second pattern is especially important because it appears in many recursion and stack problems.

## 24) Time complexity

Each element may need to move through the stack during insertion.

So total cost is:

```text
1 + 2 + 3 + ... + n = O(n²)
```

Therefore:

```text
Time Complexity = O(n²)
Space Complexity = O(n)
```

---

## 25) Why this is O(n²)

For n elements, insertion costs increase as the stack grows.

Example:

```text
first insertion -> up to 1 move
second insertion -> up to 2 moves
third insertion -> up to 3 moves
...
```

So total work is quadratic.

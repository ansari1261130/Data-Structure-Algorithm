# Recursion Revision Note — Power Set / Subsequences

Question: [Power Set using Recursion](https://www.geeksforgeeks.org/problems/power-set-using-recursion/1)

Pattern: Subsequence / Take-Not-Take / Recursion

## 1) Core idea

We are asked to generate all possible subsequences of a string.

For a string like `abc`, valid outputs are:

```text
""
"a"
"b"
"c"
"ab"
"ac"
"bc"
"abc"
```

The empty string is valid.

A subsequence keeps the original relative order of characters.

```text
abc -> "ac" is valid
abc -> "ba" is not valid
```

---

## 2) The real decision

For every character, there are only two choices:

- Take it
- Skip it

This gives the standard recursive pattern:

```text
Take / Not Take
```

For `abc`:

```text
start with a
Take a -> "a"
Skip a -> ""

Then do the same for b
Then do the same for c
```

So each level of recursion represents one character.

---

## 3) Why this is the right structure

The problem is not asking for a single answer.

It is asking for all answers.

That means every character must be explored in both states:

```text
current character can be present or absent
```

This is exactly the subsequence pattern.

---

## 4) Important state

The important state is:

- current index `i`
- current subsequence `str`

Conceptually:

```text
State = (i, str)
```

The original string itself does not change.

Only the index moves forward, and the chosen characters are accumulated into `str`.

---

## 5) Take / Not Take transitions

### Take current character

```java
helper(s, i + 1, str + s.charAt(i), list);
```

### Skip current character

```java
helper(s, i + 1, str, list);
```

Why `i + 1` in both cases?

Because after making the decision for the current character, we move to the next character.

This is the heart of the recursion.

---

## 6) Base case

When all characters have been processed:

```java
if (i == s.length()) {
    list.add(str);
    return;
}
```

This means one complete subsequence has been built.

We store it and stop exploring that branch.

---

## 7) Why empty string is included

If we skip every character:

```text
skip a -> skip b -> skip c -> ""
```

Then the empty subsequence is produced.

That is why `""` must be included in the answer list.

---

## 8) Recursion tree

For `abc`, the structure is:

```text
        ""
      /    \
    take   skip
      a      ""
     / \     / \
   ab  a   b   ""
   / \ / \ / \ / \
 abc ab ac a bc b c ""
```

Each level corresponds to one character.

At every level, we either:

- include the character
- exclude the character

---

## 9) Final Java code

```java
class Solution {

    public ArrayList<String> powerSet(String s) {
        ArrayList<String> list = new ArrayList<>();
        helper(s, 0, "", list);
        return list;
    }

    private void helper(String s, int i, String str, ArrayList<String> list) {
        if (i == s.length()) {
            list.add(str);
            return;
        }

        helper(s, i + 1, str + s.charAt(i), list);
        helper(s, i + 1, str, list);
    }
}
```

---

## 10) Why this works

Every recursive call makes a decision for the current index.

Then it continues with the next index.

Eventually, when `i == s.length()`, we have decided for every character.

At that moment, `str` represents one valid subsequence.

Since we explored both branches at each step, all subsequences are generated.

---

## 11) Complexity

Each character has 2 choices:

```text
Take or Skip
```

Therefore total subsequences = `2^n`.

Time complexity:

```text
O(n * 2^n)
```

because each of the `2^n` strings can have length up to `n`.

Space complexity:

```text
O(n)
```

for recursion stack, plus output storage.

---

## 12) Comparison with ATOI

ATOI is linear recursion:

```text
process current char -> move to next index
```

Power Set is branching recursion:

```text
current char -> take OR skip -> move to next index
```

This difference is important.

- ATOI: one path continues
- Power Set: two paths continue

---

## 13) Comparison with Generate Parentheses

Generate Parentheses:

- multiple choices
- extra constraint
- prune invalid branches

Power Set:

- multiple choices
- no validity constraint
- explore both branches

So:

```text
Generate Parentheses -> Choice + Constraint + Pruning
Power Set -> Choice + Exhaustive Exploration
```

---

## 14) Common mistakes

### Mistake 1: only taking characters

If we only take every character, we miss outputs such as:

```text
""
"a"
"b"
"c"
"ab"
```

So both branches are necessary.

### Mistake 2: forgetting the base case

At `i == s.length()`, we must store the current subsequence.

### Mistake 3: thinking the string must physically shrink

It does not need to shrink.

We can keep the same string and just move the index forward.

### Mistake 4: forgetting the empty subsequence

Skipping every element yields `""`, so it must be included.

---

## 15) Recognition signal

When a problem says:

```text
Generate all subsequences / power set / subsets
```

ask this immediately:

```text
For every element, can I take it or skip it?
```

If the answer is yes, think:

```text
TAKE / NOT TAKE
```

Then define:

```text
helper(index, currentState)
```

where currentState is whatever data the problem needs to carry.

---

## 16) Generic template

```java
void helper(int index, State state) {
    if (index == n) {
        processAnswer();
        return;
    }

    helper(index + 1, takeState());
    helper(index + 1, skipState());
}
```

This is the classic subsequence template.

---

## 17) One-line recall

```text
For every character: take it or skip it, move to next index, and when all characters are processed, save the current subsequence.
```

---

## 18) Final takeaway

The important idea is not memorizing the code.

The important idea is recognizing the pattern:

```text
Element
   /   \
 TAKE  NOT TAKE
   |      |
 recurse  recurse
```

This is the core subsequence pattern.

Once you see it, problems like:

- Power Set
- Subset Sum
- Count Subsets
- 0/1 Knapsack

all start to feel structurally similar.

---

## 19) Final recall questions

Before solving a new problem, ask:

1. Is this asking for subsequences or subsets?
2. For every element, do I have a take/skip decision?
3. What is the current index?
4. What state must I carry?
5. What is the base case?
6. Do I store the answer at the base case?

If the answer to question 2 is yes, start thinking:

```text
TAKE / NOT TAKE
```

That is the memory signal for this pattern.

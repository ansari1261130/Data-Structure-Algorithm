LeetCode 1498 — Number of Subsequences That Satisfy the Given Sum Condition

Question

LeetCode:
https://leetcode.com/problems/number-of-subsequences-that-satisfy-the-given-sum-condition/description/

Given an array nums and an integer target, return the number of non-empty subsequences such that:

minimum element + maximum element <= target

Return the answer modulo:

1_000_000_007

Example:

nums = [3,5,6,7]
target = 9

Valid:
[3]
[3,5]
[3,6]
[3,5,6]

Answer = 4

PART A — UNSORTED ARRAY

1. First Observation: TAKE / SKIP

For every element there are two choices:

TAKE
SKIP

Conceptually:

                         []
                      /      \
                  TAKE 3    SKIP 3
                    /          \
                  [3]            []
                /    \          /   \
            TAKE 5  SKIP 5   TAKE 5 SKIP 5
                 ...            ...

Every root-to-leaf path represents one subsequence.

2. What State Do We Need?

The condition is:

minimum + maximum <= target

So the brute-force recursive state is:

(i, min, max, selected)

Meaning:

i → next element to decide

min → minimum selected value so far

max → maximum selected value so far

selected → whether at least one element has been selected

3. Why Do We Need selected?

The problem asks for non-empty subsequences.

The recursion can choose:

SKIP 3
SKIP 5
SKIP 6
SKIP 7

which gives:

[]

But an empty subsequence has no meaningful:

min
max

So:

boolean selected

tracks whether we have selected at least one element.

4. Initial min and max

Before selecting anything:

min = Integer.MAX_VALUE;
max = Integer.MIN_VALUE;

When the first element is selected:

if (!selected) {
    newMin = nums[i];
    newMax = nums[i];
}

For example:

TAKE 3
→ min = 3
→ max = 3

After that, update normally.

5. TAKE Branch

Suppose:

min = 3
max = 5
current element = 6

Taking 6 gives:

newMin = min(3,6) = 3
newMax = max(5,6) = 6

Code:

int newMin = Math.min(min, nums[i]);
int newMax = Math.max(max, nums[i]);

6. SKIP Branch

If the current element is skipped, the selected subsequence does not change.

So:

min → same
max → same
selected → same
i → i + 1

Code:

int skip = subsequence(
    i + 1,
    nums,
    min,
    max,
    selected,
    target
);

7. Why take + skip?

We are counting valid subsequences.

take = valid subsequences from TAKE branch
skip = valid subsequences from SKIP branch

Therefore:

return take + skip;

Remember:

EXISTS → take || skip
COUNT  → take + skip

8. Unsorted Recursive Code

class Solution {

    public int numSubseq(int[] nums, int target) {
        return subsequence(
            0,
            nums,
            Integer.MAX_VALUE,
            Integer.MIN_VALUE,
            false,
            target
        );
    }

    private int subsequence(
            int i,
            int[] nums,
            int min,
            int max,
            boolean selected,
            int target) {

        if (i == nums.length) {
            return selected && min + max <= target ? 1 : 0;
        }

        int newMin;
        int newMax;

        if (!selected) {
            newMin = nums[i];
            newMax = nums[i];
        } else {
            newMin = Math.min(min, nums[i]);
            newMax = Math.max(max, nums[i]);
        }

        // TAKE
        int take = subsequence(
            i + 1,
            nums,
            newMin,
            newMax,
            true,
            target
        );

        // SKIP
        int skip = subsequence(
            i + 1,
            nums,
            min,
            max,
            selected,
            target
        );

        return take + skip;
    }
}

9. Why Can't We Prune in the Unsorted Array?

Example:

nums = [10,20,1]
target = 25

Suppose current selection is:

[10,20]

Then:

min = 10
max = 20

10 + 20 = 30 > 25

But 1 is still ahead.

Take 1:

[10,20,1]

min = 1
max = 20

1 + 20 = 21 <= 25

So the branch becomes valid again.

Therefore:

if (min + max > target) {
    return 0;
}

is not safe for an unsorted array.

The reason is that a future element can be smaller than the current minimum.

10. Unsorted Recursion Tree

For:

nums = [3,5,6,7]
target = 9

the tree conceptually is:

                                      helper(0, INF, -INF, false)
                                      /                              \
                                 TAKE 3                            SKIP 3
                                 /                                  \
                     helper(1, 3, 3, true)                helper(1, INF, -INF, false)
                       /            \                              /                \
                   TAKE 5          SKIP 5                    TAKE 5             SKIP 5
                   /                 \                        /                    \
       helper(2, 3, 5, true)   helper(2, 3, 3, true)    helper(2, 5, 5, true)  helper(2, INF, -INF, false)
           /      \                 /        \              /        \              /        \
       TAKE 6   SKIP 6        TAKE 6    SKIP 6       TAKE 6    SKIP 6       TAKE 6    SKIP 6
       /          \            /            \          /          \          /          \
helper(3,3,6,true) helper(3,3,5,true) helper(3,3,6,true) helper(3,3,3,true) ...
   /       \                 /      \                  /      \
TAKE 7   SKIP 7           TAKE 7  SKIP 7          TAKE 7  SKIP 7
(3+7>9)  (3+6=9)        (3+7>9) (3+5=8)      (5+7>9) (5+5=10)
  invalid  valid          invalid valid        invalid invalid

At each leaf:

valid → 1
invalid → 0

Then every parent computes:

take + skip

The useful idea is that every root-to-leaf path represents one subsequence, and each leaf contributes either 1 or 0 depending on whether that final subsequence satisfies the condition.

Example from the valid branch:

[3]        → 3 + 3 <= 9
[3,5]      → 3 + 5 <= 9
[3,6]      → 3 + 6 <= 9
[3,5,6]    → 3 + 6 <= 9

So the valid subtrees contribute to the total count.

PART B — SORTED ARRAY

11. Sort the Array

Now:

Arrays.sort(nums);

Example:

[3,5,6,7]

The important property is:

nums[i] <= nums[i+1] <= nums[i+2] ...

12. What Becomes Fixed?

Suppose we choose:

3

as the minimum selected element.

Because the array is sorted, every element to its right is:

>= 3

Therefore the minimum cannot decrease while moving right.

So once the first selected element is fixed as 3:

minimum = 3

is known.

13. Maximum Still Changes

Sorting does not mean maximum is constant.

For example:

[3]       → max = 3
[3,5]     → max = 5
[3,6]     → max = 6
[3,5,6]   → max = 6

Instead, sorting lets us find the largest allowed maximum boundary.

14. Find the Largest Allowed Maximum

For:

nums = [3,5,6,7]
target = 9

Fix:

minimum = 3

Then:

3 + max <= 9

Check:

3 + 5 = 8  ✅
3 + 6 = 9  ✅
3 + 7 = 10 ❌

So:

maximum allowed boundary = 6

Conceptually:

3   5   6 | 7
        ↑
   last valid

15. Why Can We Stop After Failure?

Because the array is sorted.

If:

3 + 7 > 9

then every later element is at least 7.

So later values cannot become smaller and rescue this condition.

Therefore once we cross the valid boundary, the rest are invalid for this fixed minimum.

16. Sorted Recursive Version With Safe Pruning

We can still use our TAKE/SKIP recursion after sorting:

class Solution {

    public int numSubseq(int[] nums, int target) {
        Arrays.sort(nums);

        return subsequence(
            0,
            nums,
            Integer.MAX_VALUE,
            Integer.MIN_VALUE,
            false,
            target
        );
    }

    private int subsequence(
            int i,
            int[] nums,
            int min,
            int max,
            boolean selected,
            int target) {

        // Safe after sorting:
        // once min + max is too large,
        // future elements cannot make it valid again.
        if (selected && min + max > target) {
            return 0;
        }

        if (i == nums.length) {
            return selected && min + max <= target ? 1 : 0;
        }

        int newMin;
        int newMax;

        if (!selected) {
            newMin = nums[i];
            newMax = nums[i];
        } else {
            newMin = Math.min(min, nums[i]);
            newMax = Math.max(max, nums[i]);
        }

        // TAKE
        int take = subsequence(
            i + 1,
            nums,
            newMin,
            newMax,
            true,
            target
        );

        // SKIP
        int skip = subsequence(
            i + 1,
            nums,
            min,
            max,
            selected,
            target
        );

        return take + skip;
    }
}

17. Why Is the Pruning Safe Now?

Suppose:

sorted nums = [3,5,6,7,8,10]
target = 9

Current:

min = 3
max = 7

Then:

3 + 7 = 10 > 9

From this point on, all future elements are:

>= 7

and the minimum cannot decrease.

So the branch cannot become valid later.

Therefore:

if (selected && min + max > target) {
    return 0;
}

is safe after sorting.

18. Sorted Tree for the Example

For:

[3,5,6,7]
target = 9

Start:

                         [ ]
                       /     \
                    TAKE 3  SKIP 3
                     [3]       []
                    /   \       / \
               TAKE 5  SKIP5  ... ...
                 [3,5]   [3]
                 /  \
             TAKE6  SKIP6
               [3,5,6] [3,5]
                 /   \      / \
              TAKE7 SKIP7 TAKE7 SKIP7
                ❌      ✅     ❌      ✅

For example:

[3,5,6,7] → 3 + 7 = 10 → invalid
[3,5,6]   → 3 + 6 = 9  → valid
[3,5,7]   → 3 + 7 = 10 → invalid
[3,5]     → 3 + 5 = 8  → valid

and similarly for [3,6] and [3].

19. The Big Optimization Insight

Brute-force recursion:

Generate every subsequence
        ↓
Find min/max
        ↓
Check condition
        ↓
Count

Sorted optimization:

Fix minimum
        ↓
Find largest valid maximum index r
        ↓
Every element between i and r is optional
        ↓
Count all TAKE/SKIP combinations directly

For:

[3,5,6,7]
target = 9

fix minimum 3.

Largest valid maximum:

6

The optional elements are:

5,6

Each has:

TAKE / SKIP

So:

2 × 2 = 4

valid subsequences:

[3]
[3,5]
[3,6]
[3,5,6]

20. Important Distinction About Maximum

Do not say:

"After sorting, max is fixed."

Correct:

"After sorting, once the minimum is fixed,
we can find the largest allowed maximum boundary."

Individual subsequences can still have:

max = 3
max = 5
max = 6

We simply do not need to evaluate each one separately in the final optimization.

22. Recursion Lesson

A recursive state is not necessarily the final optimized state.

Brute force state:

(i, min, max, selected)

Optimized sorted idea:

i = current minimum index
r = largest allowed maximum index

Then:

i+1 ... r

are optional.

The optimization changes:

"generate every branch"

into:

"count an entire group of branches"

23. Complexity

Unsorted brute force

There are:

2^n

possible subsequences.

So:

Time: O(2^n)
Space: O(n)

for recursion stack, excluding output.

Sorted recursive + pruning

Sorting takes:

O(n log n)

but recursion can still be exponential in the worst case:

O(2^n)

Pruning can reduce work in practice.

Final optimized approach

The intended optimization is:

sorting
+
find valid right boundary
+
count combinations using powers of 2

This avoids generating every valid subsequence individually.

25. Final Recall Questions

Unsorted

1. What are the choices?
   TAKE / SKIP

2. What state changes?
   i, min, max, selected

3. What happens on SKIP?
   min/max/selected stay the same

4. What happens at the leaf?
   selected && min + max <= target

5. How do we combine?
   take + skip

Sorted

1. Why sort?
   To make the array monotonic.

2. What can be fixed?
   The minimum.

3. What do we find?
   The largest valid maximum boundary.

4. Why can we stop after failure?
   Future values are larger.

5. What are the middle elements?
   Independent TAKE/SKIP choices.

6. How can the whole group be counted?
   2^(number of optional elements)

One-Line Memory Trick

UNSORTED:
TAKE/SKIP → carry min/max → check at leaf

SORTED:
fix minimum → find maximum boundary → count TAKE/SKIP combinations

The key optimization transition is:

Individual subsequences
        ↓
Group of valid subsequences
        ↓
Count the group directly

Power Set / Subsets — Recursion & Backtracking
https://leetcode.com/problems/subsets/
Problem

Given an integer array nums containing distinct elements, return all possible subsets (the power set).

Example:

nums = [1, 2, 3]

Possible subsets:
[]
[1]
[2]
[3]
[1,2]
[1,3]
[2,3]
[1,2,3]

There are 2^n possible subsets.

1. Core Observation

For every element, there are exactly two choices:

TAKE the element
SKIP the element

For:

nums = [1, 2, 3]

the recursion explores both choices for 1, then both choices for 2, then both choices for 3.

This creates a binary recursion tree.

2. Complete Recursion Tree

For nums = [1,2,3]:

                                      helper(0, [])
                                     /            \
                              TAKE 1              SKIP 1
                                /                    \
                         helper(1,[1])          helper(1,[])
                           /       \                /       \
                     TAKE 2       SKIP 2       TAKE 2       SKIP 2
                        /             \            /             \
              helper(2,[1,2])   helper(2,[1]) helper(2,[2])   helper(2,[])
                 /      \          /    \        /    \         /    \
             TAKE 3   SKIP 3    TAKE 3 SKIP 3  TAKE 3 SKIP 3   TAKE 3 SKIP 3
                /         \       /       \      /       \       /       \
        [1,2,3]        [1,2]   [1,3]     [1]   [2,3]      [2]    [3]       []


The leaf nodes are the final subsets:

[1,2,3]
[1,2]
[1,3]
[1]
[2,3]
[2]
[3]
[]

So:

Number of leaves = 2^3 = 8

For n elements:

Number of leaves = 2^n

3. What Does helper(i, ...) Mean?

This is the most important recursion definition.

helper(i, nums, subList, list)

means:

Decide what to do with every element from index i onward, while subList contains the elements selected so far.

For example:

helper(0, ...)

means:

No element has been decided yet.
Decide for 1, 2, 3.

helper(1, ...)

means:

Index 0 has already been decided.
Now decide for 2, 3.

helper(2, ...)

means:

Indices 0 and 1 have already been decided.
Now decide for 3.

helper(3, ...)

means:

All elements have been decided.
One complete subset is ready.

4. Why Is the Base Case i == nums.length?

For:

nums = [1,2,3]

valid indices are:

0 → 1
1 → 2
2 → 3

After deciding whether to TAKE or SKIP 3, we call:

helper(3, ...)

There is no element at index 3.

That means:

Every element has already received a TAKE/SKIP decision.

Therefore:

if (i == nums.length)

is the correct base case.

Important

This would be wrong:

if (i == nums.length - 1)

because the last element still needs its TAKE/SKIP decision.

5. Same subList or New subList?

Use the same working subList.

Create it once:

List<Integer> subList = new ArrayList<>();

Then modify it during recursion:

ADD
 ↓
RECURSE
 ↓
REMOVE
 ↓
RECURSE

Example:

[]
 ↓ TAKE 1
[1]
 ↓ TAKE 2
[1,2]
 ↓ TAKE 3
[1,2,3]
 ↓ RETURN
[1,2]
 ↓ SKIP 3
...

We do not need a new subList at every recursion level.

6. Why Do We Remove the Element?

This is the backtracking step.

Suppose:

subList.add(nums[i]);
helper(i + 1, ...);

We chose nums[i].

After completely exploring that branch, we need to explore the opposite decision:

Do NOT choose nums[i]

So we undo our previous choice:

subList.remove(subList.size() - 1);

Therefore the complete pattern is:

TAKE
 ↓
RECURSE
 ↓
UNDO
 ↓
SKIP
 ↓
RECURSE

This is the fundamental Take/Skip backtracking pattern.

7. Why Do We Save a Copy?

At the base case:

list.add(new ArrayList<>(subList));

The subList is one mutable working object.

The answer list needs an independent snapshot.

Think of it like:

subList = working basket
list     = collection of photographs

The basket keeps changing:

[]
[1]
[1,2]
[1,2,3]
[1,2]
[1]
...

But each saved answer must remain unchanged.

Therefore:

new ArrayList<>(subList)

creates a copy.

Wrong

list.add(subList);

This stores the same mutable object repeatedly.

Correct

list.add(new ArrayList<>(subList));

This stores a snapshot.

8. Complete Correct Code

class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        List<Integer> subList = new ArrayList<>();
        List<List<Integer>> list = new ArrayList<>();

        helper(0, nums, subList, list);

        return list;
    }

    private void helper(
            int i,
            int[] nums,
            List<Integer> subList,
            List<List<Integer>> list) {

        // All elements have been decided
        if (i == nums.length) {
            list.add(new ArrayList<>(subList));
            return;
        }

        // TAKE nums[i]
        subList.add(nums[i]);
        helper(i + 1, nums, subList, list);

        // UNDO the TAKE
        subList.remove(subList.size() - 1);

        // SKIP nums[i]
        helper(i + 1, nums, subList, list);
    }
}

10. Leaf Order

The recursion reaches the leaves in this order:

[1,2,3]
[1,2]
[1,3]
[1]
[2,3]
[2]
[3]
[]

The exact output order is not important unless the problem explicitly requires one.

The important part is that all 2^n subsets are generated.

11. Recursion State

The important state is:

(i, subList)

i

Answers:

Which element should I decide next?

subList

Answers:

Which elements have I selected so far?

Example:

i = 2
subList = [1]

means:

1 has already been selected.

Now decide whether to TAKE or SKIP
the remaining elements starting from index 2.

12. What Is Getting Smaller?

At every recursive call:

helper(i + 1, ...)

Therefore:

i → i + 1

and the number of undecided elements decreases.

Example:

helper(0)
    ↓
helper(1)
    ↓
helper(2)
    ↓
helper(3)

At:

helper(3)

all elements are processed.

This is the shrinking part of the recursion.

13. The Generic Take/Skip Pattern

Whenever every element has two choices:

                 element
                /       \
             TAKE       SKIP

the recursion often looks like:

// TAKE
choose(element);
helper(next);

// UNDO
undo();

// SKIP
helper(next);

For subsets:

subList.add(nums[i]);
helper(i + 1, nums, subList, list);

subList.remove(subList.size() - 1);

helper(i + 1, nums, subList, list);

14. Why This Is Backtracking

Backtracking is essentially:

Make a choice
    ↓
Explore the choice
    ↓
Undo the choice
    ↓
Try another choice

For this problem:

TAKE
 ↓
EXPLORE
 ↓
REMOVE
 ↓
SKIP
 ↓
EXPLORE

The remove() is the undo operation.

15. Why We Don't Create a Tree Object

We say that the algorithm creates a recursion tree, but we do not need:

class TreeNode { ... }

The recursive calls themselves form the conceptual tree.

For example:

helper(0, [])
├── helper(1, [1])       // TAKE 1
│   ├── helper(2,[1,2])  // TAKE 2
│   └── helper(2,[1])    // SKIP 2
└── helper(1, [])        // SKIP 1
    ├── helper(2,[2])     // TAKE 2
    └── helper(2, [])     // SKIP 2

The Java call stack keeps track of the current path.

16. Complexity

There are:

2^n

subsets.

At each leaf, we copy the current subset:

new ArrayList<>(subList)

which can take up to O(n).

Therefore:

Time Complexity = O(n × 2^n)

Output space:

O(n × 2^n)

because there are 2^n subsets and each can contain up to n elements.

Recursion depth:

O(n)

17. Common Mistakes

Mistake 1 — Wrong base case

Wrong:

if (i == nums.length - 1)

Correct:

if (i == nums.length)

Mistake 2 — Saving the same mutable object

Wrong:

list.add(subList);

Correct:

list.add(new ArrayList<>(subList));

Mistake 3 — Creating a new working list every call

Not required.

Use one working list and mutate it:

ADD → RECURSE → REMOVE

Mistake 4 — Forgetting the undo

Wrong:

subList.add(nums[i]);
helper(i + 1, ...);

helper(i + 1, ...);

The second branch still contains the previous choice.

Correct:

subList.add(nums[i]);
helper(i + 1, ...);

subList.remove(subList.size() - 1);

helper(i + 1, ...);

18. How to Recognize This Pattern

When a problem says:

Generate all subsets.

Ask:

For every element:
    Can I TAKE it?
    Can I SKIP it?

If yes:

TAKE / SKIP recursion

Then identify:

State       → i + current selection
Choice      → TAKE / SKIP
Smaller     → i + 1
Base case   → i == nums.length
Undo        → remove last selected element
Result      → copy current selection

19. Five Questions to Ask Before Coding

Q1. What are my choices?

TAKE / SKIP

Q2. What is getting smaller?

i → i + 1

Q3. What does my helper mean?

helper(i) =
decide for all elements from index i onward.

Q4. When is the problem completely solved?

i == nums.length

Q5. Do I need to undo my choice?

Yes.

Because the same working subList is reused:

ADD → RECURSE → REMOVE

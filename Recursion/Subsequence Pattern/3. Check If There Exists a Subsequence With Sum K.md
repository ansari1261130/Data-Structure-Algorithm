Check If There Exists a Subsequence With Sum K — Recursion

Question

GeeksforGeeks:
https://www.geeksforgeeks.org/problems/check-if-there-exists-a-subsequence-with-sum-k/1

1. Problem

Given an array arr and an integer k, determine whether there exists at least one subsequence whose sum is exactly k.

Example:

arr = [1, 2, 3]
k = 5

Possible subsequences include:

[]
[1]
[2]
[3]
[1,2]
[1,3]       ← sum = 4
[2,3]       ← sum = 5
[1,2,3]     ← sum = 6

Answer = true

We do not need to return all subsequences.

We only need:

true / false

2. First Question: What Choices Do We Have?

For every element, there are two choices:

TAKE
SKIP

For:

arr = [1,2,3]

the decision tree starts like:

                 []
                /  \
             TAKE 1 SKIP 1
               /      \
             [1]       []

Then from each state, we again decide for 2.

Then for 3.

This is the classic:

TAKE / SKIP

recursion pattern.

3. What Does the Helper Function Mean?

We use:

subsequence(i, arr, sum, k)

Meaning:

Starting from index i, can I choose some remaining elements such that the final sum becomes k, given that the current sum is already sum?

So the state is:

(i, sum)

Where:

i

Tells us:

Which element should I decide next?

sum

Tells us:

What is the sum of the elements I have already chosen?

4. Why Do We Pass i + 1?

Suppose:

arr = [1,2,3]

Initially:

i = 0
arr[i] = 1

After making a decision about 1, that element is finished.

Therefore we move to:

i + 1 = 1

which means:

Now decide for 2.

So:

i:
0 → 1 → 2 → 3

This has nothing to do with adding or subtracting the sum.

i and sum are two different pieces of state.

5. i + 1 and sum + arr[i] Do Different Jobs

Consider:

boolean take =
    subsequence(i + 1, arr, sum + arr[i], k);

There are two separate operations here:

i + 1
   ↓
Move to the next element

sum + arr[i]
   ↓
Include the current element in the sum

Example:

Current state:

i = 1
sum = 2
arr[i] = 5

TAKE 5:

next i   = 2
next sum = 2 + 5 = 7

So the child call becomes:

subsequence(2, arr, 7, k);

6. What Happens When We SKIP?

If we skip the current element, we do not add it to the sum.

So:

boolean skip =
    subsequence(i + 1, arr, sum, k);

Example:

Current state:

i = 1
sum = 2
arr[i] = 5

SKIP 5:

next i   = 2
next sum = 2

So:

subsequence(2, arr, 2, k);

7. Important Correction

Do not write:

boolean skip =
    subsequence(i + 1, arr, sum - arr[i], k);

because skipping means:

"I am not using this element."

It does not mean:

"Subtract this element from the sum."

The correct skip state is:

subsequence(i + 1, arr, sum, k);

8. Why Don't We Need sum -= arr[i]?

This is an important difference from the Subsets problem.

For the sum problem, we can pass a new value:

sum + arr[i]

The int value is passed to the child call.

Example:

Parent:
sum = 2

TAKE child:
sum = 7

Parent:
sum is still 2

The parent's sum does not become 7.

Therefore there is no need to write:

sum -= arr[i];

after the recursive call.

9. Contrast With the Subsets Problem

Subsets

We change the same mutable list:

subList.add(nums[i]);
helper(..., subList);

subList.remove(subList.size() - 1);

Why remove?

Because the same List object is being modified and passed to child calls.

Subsequence Sum

We pass a new integer value:

helper(i + 1, arr, sum + arr[i], k);

The parent still has its original sum.

Therefore:

List:
ADD → RECURSE → REMOVE

Sum:
new value → RECURSE

Mental rule:

Same mutable object changed → explicit undo is usually needed.

Primitive value calculated and passed → the parent value remains unchanged.

10. Base Case

When:

if (i == arr.length)

there are no elements left to process.

So now we have reached one complete subsequence decision.

The only question left is:

Is sum == k?

Therefore:

if (i == arr.length) {
    return sum == k;
}

This returns:

true

if this particular path produced sum k.

Otherwise:

false

11. Why Is There a Final return Too?

This was one of the most important recursion questions.

The base case:

return sum == k;

returns the answer for one leaf/path.

But the parent still has two possibilities:

TAKE
SKIP

So the parent receives two results:

take
skip

and must combine them.

Because the problem asks:

Does there exist at least one valid subsequence?

we use:

return take || skip;

So:

BASE RETURN
    ↓
gives one path's answer

PARENT RETURN
    ↓
combines child answers
    ↓
passes the subtree answer upward

12. Why Does return Travel One Stack Frame at a Time?

Suppose we have:

Parent
  ↓
Child
  ↓
Grandchild
  ↓
Base

Base executes:

return true;

That true does not immediately jump to the original function.

It returns to the function that called the base case.

Then that function may return another value.

Then that value goes to its parent.

So:

Base
  ↓ true
Parent
  ↓ true
Grandparent
  ↓ true
Original call

Each stack frame gets the child's result and decides what its own result should be.

13. Complete Recursion Tree

For:

arr = [1,2,3]
k = 5

the conceptual recursion tree is:

                                      subsequence(0, sum=0)
                                      /                  \
                               TAKE 1                   SKIP 1
                                 /                         \
                    subsequence(1, sum=1)        subsequence(1, sum=0)
                       /          \                  /          \
                  TAKE 2        SKIP 2          TAKE 2        SKIP 2
                    /               \               /               \
      subsequence(2,3)        subsequence(2,1)  subsequence(2,2)  subsequence(2,0)
           /       \                /    \          /    \            /    \
      TAKE 3      SKIP 3       TAKE 3  SKIP 3   TAKE 3 SKIP 3      TAKE 3 SKIP 3
         /            \            /      \         /      \           /      \
     sum=6          sum=3      sum=4    sum=1     sum=5   sum=2       sum=3   sum=0
      false          false      false   false     TRUE    false      false   false


At the sum = 5 leaf:

return true

That result travels upward:

sum=5 leaf
    ↓ true
parent
    ↓ take = true
parent returns true
    ↓
higher parent receives true
    ↓
higher parent returns true
    ↓
...

Eventually the original call returns:

true

14. Complete Code

class Solution {
    public boolean checkSubsequenceSum(int[] arr, int k) {
        return subsequence(0, arr, 0, k);
    }

    private boolean subsequence(
            int i,
            int[] arr,
            int sum,
            int k) {

        // All elements have been decided
        if (i == arr.length) {
            return sum == k;
        }

        // TAKE current element
        boolean take =
                subsequence(i + 1, arr, sum + arr[i], k);

        // SKIP current element
        boolean skip =
                subsequence(i + 1, arr, sum, k);

        // If either branch finds a valid subsequence
        return take || skip;
    }
}

Input:

arr = [1,2,3]

Start:

subsequence(1, 1)

false

subsequence(2, 3)

subsequence(3, 3)

Base:

3 == 5
false

Therefore this subsequence(2,3) call returns:

false || false

from a state with sum 0 gives:

0 + 2 = 2

That true propagates upward.

16. The Most Important Mental Model

Think of every recursive call as asking:

"Can my subtree find a valid subsequence?"

A leaf answers directly:

sum == k ?

A parent asks its children:

Can TAKE find one?
OR
Can SKIP find one?

Therefore:

Leaf:
return sum == k

Parent:
return take || skip

17. Why || and Not &&?

The question is:

Does there exist a subsequence?

We need only one branch to succeed.

So:

true OR false = true
false OR true = true
true OR true = true
false OR false = false

Therefore:

return take || skip;

If the problem instead required:

Both branches must satisfy some condition

then && might be appropriate, but that is not this problem.

18. Backtracking vs Returning a Result

There are two different ideas here.

Backtracking

Used when you mutate a shared structure and need to restore it.

Example:

subList.add(nums[i]);
helper(...);
subList.remove(subList.size() - 1);

Pattern:

CHANGE
 ↓
RECURSE
 ↓
UNDO

Returning a Result

Used when a child must tell the parent what happened.

Example:

boolean take = helper(...);
boolean skip = helper(...);

return take || skip;

Pattern:

CHILD ANSWER
 ↓
PARENT USES ANSWER
 ↓
PARENT RETURNS ANSWER

These are related, but they solve two different problems.

20. Common Mistakes

Mistake 1

boolean skip =
    subsequence(i + 1, arr, sum - arr[i], k);

Wrong.

Correct:

boolean skip =
    subsequence(i + 1, arr, sum, k);

Mistake 2

Calling the recursion but ignoring its result:

subsequence(i + 1, ...);

When the result matters, store it:

boolean take = subsequence(i + 1, ...);

Mistake 3

Always returning true

return true;

Wrong because a branch can fail.

The result must depend on the recursive branches:

return take || skip;

Mistake 4

Wrong base case:

if (i == arr.length - 1)

Correct:

if (i == arr.length)

because the last element still needs its TAKE/SKIP decision.

21. Complexity

There are two choices for every element:

TAKE / SKIP

So the recursion tree has:

2^n

leaves.

Each recursive call does O(1) work apart from the recursive calls.

Therefore:

Time Complexity = O(2^n)

Recursion depth:

O(n)

Auxiliary recursion stack:

O(n)

Unlike the Subsets problem, we do not have to store all subsets.

22. How to Recognize This Pattern

When you see:

"Does there exist a subsequence/subset whose sum is K?"

ask:

For each element:
    TAKE?
    SKIP?

Then identify:

State:
(i, sum)

Choice:
TAKE / SKIP

Smaller problem:
i + 1

Base:
i == arr.length

Leaf answer:
sum == k

Combine:
take || skip

23. Five Questions Before Coding

Q1. What are my choices?

TAKE / SKIP

Q2. What is getting smaller?

i → i + 1

Q3. What state do I need to remember?

i + current sum

Q4. When is one complete decision path finished?

i == arr.length

Q5. How do I combine child answers?

Because we need existence:

TAKE OR SKIP

so:

return take || skip;

Do not memorize the final code first.

Try to derive it:

       ↓
2. TAKE or SKIP.
       ↓
3. Move to i + 1.
       ↓
4. TAKE → sum + arr[i].
       ↓

       ↓

       ↓

       ↓

       ↓

RECURSE

The key distinction:

Subsets needs backtracking because the same mutable List is changed.

Subsequence Sum does not need sum -= arr[i] because sum + arr[i] is passed as a new primitive value to the child call.

Final Takeaway

The two concepts to remember are:

1. STATE PROPAGATION
   i tells us where we are.
   sum tells us what we have selected.

2. RESULT PROPAGATION
   Base case produces true/false.
   Parent receives child results.
   Parent combines them and returns upward.

So recursion has two different directions of information:

State goes DOWN:
parent → child

Answer goes UP:
child → parent

This is the key idea behind this entire recursion pattern.


LeetCode 216 — Combination Sum III

Question

LeetCode:
https://leetcode.com/problems/combination-sum-iii/

Find all valid combinations of k numbers that sum up to n, subject to:

1. Only numbers from 1 through 9 may be used.
2. Each number may be used at most once.
3. The answer should contain all valid combinations.

Example:

k = 3
n = 7

Answer:
[[1,2,4]]

Another example:

k = 3
n = 9

Answer:
[[1,2,6],
 [1,3,5],
 [2,3,4]]

1. First Understand the Recursion

The first question should be:

At this recursion level, what can I choose next?

We can choose any number from:

idx ... 9

So this is a multiple-choice backtracking problem.

That naturally gives us:

for (int i = idx; i <= 9; i++)

2. Core Pattern

The pattern is:

FOR EACH POSSIBLE CHOICE

    DO
      ↓
    EXPLORE
      ↓
    UNDO
      ↓
    NEXT CHOICE

In code:

for (int i = idx; i <= 9; i++) {

    subList.add(i);                  // DO

    combination(
        i + 1,
        k - 1,
        n - i,
        subList,
        list
    );                                // EXPLORE

    subList.remove(subList.size() - 1); // UNDO
}

This is the same:

DO → EXPLORE → UNDO

pattern we used in Combination Sum II and Subsets II.

3. What Does Each Parameter Mean?

Our helper is:

combination(idx, k, n, subList, list)

Each parameter has a different job.

idx

Which number can I start choosing from?

Example:

idx = 1
→ choices: 1,2,3,...,9

idx = 4
→ choices: 4,5,6,7,8,9

k

How many more numbers do I need to select?

Initially:

k = required number of elements

When we choose one number:

k → k - 1

n

How much sum is still remaining?

When we choose i:

n → n - i

Example:

n = 7
choose 2
remaining n = 5

subList

Which numbers have I selected so far?

list

Stores all completed valid combinations.

4. The Three Important State Changes

When we TAKE i:

idx → i + 1
k   → k - 1
n   → n - i

Why?

i + 1

The same number cannot be reused.

k - 1

One required number has been selected.

n - i

We have already contributed i to the required sum.

So:

TAKE i
↓
one number used
↓
one fewer number required
↓
sum requirement decreases by i
↓
next recursion starts after i

5. Why Is i + 1 Used?

Numbers can be used only once.

Suppose:

[1,2,4]

After choosing:

2

we cannot choose the same 2 again.

So the next recursion starts from:

3

via:

combination(i + 1, ...);

This is the same idea as Combination Sum II.

6. Why Is There No SKIP Recursive Call?

This is an important difference from binary TAKE/SKIP recursion.

We have:

for (int i = idx; i <= 9; i++)

The loop itself naturally explores the possible skip choices.

Example:

idx = 1

The loop tries:

i = 1
i = 2
i = 3
...

Choosing 2 instead of 1 effectively means:

1 was skipped

Choosing 3 means:

1 and 2 were skipped

Therefore we don't need a separate:

skip(...)

recursive call.

The for loop already enumerates the sibling choices.

7. Recursion Tree

Example:

k = 2
n = 4

We need two distinct numbers whose sum is 4.

Start:

combination(idx=1, k=2, n=4, [])

Conceptual tree:

                                                            combination(1, 2, 4, [])
                                            /          |          |          \
                                     choose 1   choose 2   choose 3   choose 4
                                         [1]        [2]        [3]        [4]
                                            /            |          |          \
                         combination(2,1,3)  combination(3,1,2)  combination(4,1,1)  ...
                                    /      \             /      \          /      \
                            choose 2  choose 3    choose 3  choose 4  choose 4  ...
                             sum 3     sum 4       sum 5     sum 6     sum 7
                             invalid   VALID      invalid   invalid   invalid

Only valid combination:

[1,3]

because:

1 + 3 = 4

At every node, the loop creates the sibling choices. After choosing i, the
child starts at i + 1, so the same number cannot be selected again.

9. Base Case

The correct stopping condition is:

if (k == 0) {
    if (n == 0) {
        list.add(new ArrayList<>(subList));
    }
    return;
}

Meaning:

We have selected exactly k required numbers.
        ↓
If remaining sum is also zero:
        ↓
Valid combination.

So:

k == 0
AND
n == 0
→ save answer

Otherwise:

k == 0
AND
n != 0
→ invalid branch

10. Why Is k == 0 the Base Case?

Because k represents:

numbers still needed

Suppose:

k = 3

Initially we need:

3 numbers

Take one:

k = 2

Take another:

k = 1

Take another:

k = 0

Now the required number of selections has been completed.

Therefore this is the natural point where we can check whether the sum requirement is also complete.

11. Why Do We Also Check n == 0?

Because selecting exactly k numbers isn't enough.

Example:

k = 3
n = 7

Suppose we select:

[1,2,3]

Then:

k = 0
n = 1

We selected 3 numbers, but their sum is:

1 + 2 + 3 = 6

not 7.

So it is invalid.

Therefore:

if (k == 0) {
    if (n == 0) {
        save
    }
    return;
}

12. Why Is i <= 9?

The problem allows only numbers:

1 through 9

So:

for (int i = idx; i <= 9; i++)

enumerates all allowed numbers.

Once:

i = 10

the loop condition:

10 <= 9

is false.

No more choices exist.

13. Why Does the Recursion Naturally Stop?

There are two ways a branch can stop.

Case 1 — k == 0

We know no more numbers need to be selected.

We return.

Case 2 — No numbers remain in the loop

Eventually:

idx > 9

Then:

for (int i = idx; i <= 9; i++)

does not execute.

The method naturally returns.

This is similar to what we saw in Subsets II.

14. Complete Recursive Code

class Solution {

    public List<List<Integer></integer>> combinationSum3(int k, int n) {

        List<Integer></integer> subList = new ArrayList<>();
        List<List<Integer></integer>> list = new ArrayList<>();

        combination(1, k, n, subList, list);

        return list;
    }

    private void combination(
            int idx,
            int k,
            int n,
            List<Integer></integer> subList,
            List<List<Integer></integer>> list) {

        if (k == 0) {
            if (n == 0) {
                list.add(new ArrayList<>(subList));
            }
            return;
        }

        for (int i = idx; i <= 9; i++) {

            if (i <= n) {

                // DO
                subList.add(i);

                // EXPLORE
                combination(
                    i + 1,
                    k - 1,
                    n - i,
                    subList,
                    list
                );

                // UNDO
                subList.remove(subList.size() - 1);
            }
        }
    }
}

15. Why i <= n?

If:

i > n

then choosing i would immediately make the remaining sum negative:

n - i < 0

Since all allowed numbers are positive, we don't need that branch.

Example:

n = 4

Trying:

i = 5

would give:

4 - 5 = -1

There is no way to recover to zero by adding positive numbers.

So:

if (i <= n)

prevents that branch.

16. A Safe Optimization

Because the loop is increasing:

i = idx, idx+1, idx+2, ...

and:

i > n

means the current candidate is too large.

All later candidates are even larger.

Therefore, after sorting isn't even necessary here because the loop itself is already going through:

1,2,3,...,9

If:

i > n

we can safely break:

if (i > n) {
    break;
}

So instead of:

if (i <= n) {
    ...
}

we could do:

if (i > n) {
    break;
}

then process the candidate.

This is optional for understanding the recursion.

17. DO → EXPLORE → UNDO

Your code:

subList.add(i);

combination(
    i + 1,
    k - 1,
    n - i,
    subList,
    list
);

subList.remove(subList.size() - 1);

means:

DO
↓
choose i

EXPLORE
↓
continue with i+1

UNDO
↓
remove i

NEXT
↓
for loop tries next i

This is exactly the backtracking pattern.

18. Why Does the Loop Replace the Explicit SKIP Branch?

In binary recursion:

TAKE / SKIP

we might write:

take();
skip();

But here the next choice can be:

idx
idx+1
idx+2
...
9

so the loop represents all sibling choices.

Example:

idx = 2

means:

Try 2
Try 3
Try 4
Try 5
...
Try 9

Therefore no explicit:

skip()

call is necessary.

19. i++ vs Recursive i + 1

Exactly the same concept we studied before.

Suppose:

Parent:
idx = 1

Loop chooses:

i = 3

Then child gets:

idx = i + 1 = 4

Child explores:

4,5,6,7,8,9

After child returns, the parent loop continues:

i++

and tries:

i = 4

These happen in different stack frames.

So:

recursive i+1
=============

child's start

loop i++
========

parent's next choice

Not:

i+2

20. Why Is This Similar to Combination Sum II?

Very similar.

Combination Sum II

for (int i = idx; i < n; i++)

Then:

TAKE
→ recurse(i+1)
→ undo

Combination Sum III

for (int i = idx; i <= 9; i++)

Then:

TAKE
→ recurse(i+1)
→ undo

The difference is mainly the available choices:

Combination Sum II:
choices come from the input array

Combination Sum III:
choices are fixed as 1..9

And Combination Sum III also tracks:

k = how many numbers remain to choose

21. Comparison of the Three Problems

Combination Sum I

Can reuse element?
YES

TAKE:
i stays same

SKIP:
i + 1

Combination Sum II

Can reuse array element?
NO

FOR choices
TAKE:

Duplicates:

Combination Sum III

Numbers available:
1..9

NO

22. How To Derive Combination Sum III

Do not memorize the code.

Ask:

Q1. What am I constructing?

A combination of numbers.

Q2. What choices are available?

Numbers:

1..9

So:

for (...)

Q3. Can a number be reused?

No.

So:

i + 1

Q4. What else must be tracked?

Exactly k numbers are required.

So:

k

must be part of the state.

Q5. What is left to achieve?

Remaining sum:

n

k == 0

23. State Definition

The helper:

combination(idx, k, n, subList, list)

can be mentally read as:

Starting from number idx, choose exactly k more numbers whose remaining sum is n.

That single sentence explains the entire recursion.

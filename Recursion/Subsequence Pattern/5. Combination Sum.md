
Combination Sum — Recursion, Target State & TAKE/SKIP

Problem [leetcode.com/problems/combination-sum](https://leetcode.com/problems/combination-sum/)

Given candidates and target, return all unique combinations whose sum is target.

A candidate may be used unlimited times.

Example:

candidates = [2,3,6,7]
target = 7

Valid:
[2,2,3]
[7]

1. Core Recursion

For every candidate we have:

TAKE
SKIP

But Combination Sum has an important difference:

The same candidate can be selected again.

Therefore:

TAKE  → i stays the same
SKIP  → i becomes i + 1

2. Meaning of the Parameters

Our helper is:

subsequence(i, candidates, subList, list, target)

Think:

i
↓
Which candidate am I currently considering?

target
↓
How much sum is still remaining?

subList
↓
Which candidates have I selected so far?

3. Why Does target Change?

Suppose:

target = 7
candidates[i] = 2

If we TAKE 2, remaining target becomes:

7 - 2 = 5

So:

subsequence(
    i,
    candidates,
    subList,
    list,
    target - candidates[i]
);

The child gets 5.

4. Does the Parent target Change?

No.

This:

subsequence(i, candidates, subList, list, target - candidates[i]);

does not modify the parent's target.

Example:

Parent:
target = 7

TAKE 2
   ↓

Child:
target = 5

When the child returns, the parent still has:

target = 7

because int is a primitive value passed to the child call.

5. Why Doesn't Target Need Backtracking?

We are passing a new value:

target - candidates[i]

We are NOT doing:

target -= candidates[i];

So there is no need for:

target += candidates[i];

The parent value remains unchanged.

Think:

Parent target = 7
       ↓
Child receives 5
       ↓
Child returns
       ↓
Parent still has 7

6. Why Does subList Need remove()?

subList is a mutable object.

subList.add(candidates[i]);

changes the same list object that is passed to the child.

Example:

Before TAKE:
[]

After TAKE:
[2]

Child also sees:
[2]

Child returns:
[2] still exists

Now we want to explore SKIP, so we must undo:

subList.remove(subList.size() - 1);

Therefore:

List:
ADD → RECURSE → REMOVE

Target:
target - value → RECURSE

7. TAKE Branch

subList.add(candidates[i]);

subsequence(
    i,
    candidates,
    subList,
    list,
    target - candidates[i]
);

subList.remove(subList.size() - 1);

TAKE means:

i       → same
target  → decreases
subList → add candidate
after return → remove candidate

8. SKIP Branch

subsequence(
    i + 1,
    candidates,
    subList,
    list,
    target
);

SKIP means:

i       → i + 1
target  → same
subList → same

9. Why Does TAKE Keep the Same i?

Because the same candidate can be reused.

Example:

candidates = [2,3]
target = 7

We can use:

2
2
2
3

to make:

[2,2,3]

So:

TAKE 2
 ↓
i stays same
 ↓
TAKE 2 again

Tree:

                (i=0, target=7, [])
                       /              
                  TAKE 2              SKIP 2
                    /                    
        (i=0,target=5,[2])        (i=1,target=7,[])
              /       
         TAKE 2      SKIP 2
            /            
(i=0,target=3,[2,2])   (i=1,target=5,[2])

The key:

TAKE → same i
SKIP → i + 1

Complete recursion tree for candidates = [2,3] and target = 7:

                              (i=0, target=7, [])
                              /                  \
                         TAKE 2                SKIP 2
                           /                      \
              (i=0, target=5, [2])       (i=1, target=7, [])
                       /        \                    /        \
                  TAKE 2      SKIP 2              TAKE 3      SKIP 3
                    /             \                /             \
       (i=0, target=3, [2,2])  (i=1, target=5, [2])  (i=1, target=4, [3])  (i=2, target=7, [])
                /       \              /       \               /       \
           TAKE 2   SKIP 2        TAKE 3   SKIP 3          STOP       STOP
              /          \           /          \
 (i=0,target=1,[2,2,2]) (i=1,target=3,[2,2]) (i=1,target=2,[2,3]) (i=2,target=5,[2])
          STOP              /       \              /       \             STOP
                         TAKE 3   SKIP 3       TAKE 3   SKIP 3
                            /          \           /          \
             (i=1,target=0,[2,2,3])  STOP  (i=1,target=-1,[2,3,3])  STOP
                    VALID

The successful path is:

(i=0, target=7, [])
    TAKE 2
(i=0, target=5, [2])
    TAKE 2
(i=0, target=3, [2,2])
    SKIP 2
(i=1, target=3, [2,2])
    TAKE 3
(i=1, target=0, [2,2,3])

When target becomes 0, the combination is saved. Notice that TAKE keeps i
unchanged, allowing 2 to be selected more than once. SKIP moves to the next
candidate, so 2 is never considered again after it is skipped.

10. Base Cases

A clean base case is:

if (target == 0) {
    list.add(new ArrayList<>(subList));
    return;
}

Meaning:

We have formed the target exactly, so one valid combination has been found.

Also stop when:

if (i == candidates.length) {
    return;
}

Meaning:

There are no more candidates.

11. Complete Recursive Code

class Solution {
    public List<List<Integer></integer>> combinationSum(int[] candidates, int target) {
        List<Integer></integer> subList = new ArrayList<>();
        List<List<Integer></integer>> list = new ArrayList<>();

        subsequence(0, candidates, subList, list, target);

        return list;
    }

    private void subsequence(
            int i,
            int[] candidates,
            List<Integer></integer> subList,
            List<List<Integer></integer>> list,
            int target) {

        if (target == 0) {
            list.add(new ArrayList<>(subList));
            return;
        }

        if (i == candidates.length) {
            return;
        }

        // TAKE
        if (candidates[i] <= target) {
            subList.add(candidates[i]);

            subsequence(
                i,
                candidates,
                subList,
                list,
                target - candidates[i]
            );

            // BACKTRACK
            subList.remove(subList.size() - 1);
        }

        // SKIP
        subsequence(
            i + 1,
            candidates,
            subList,
            list,
            target
        );
    }
}

↓

13. Compare With Subsets

Subsets

Every element can be used at most once:

TAKE → i + 1
SKIP → i + 1

Combination Sum

The same element can be reused:

TAKE → i
SKIP → i + 1

This is the main difference.

14. Compare With Subsequence Sum

Subsequence Sum

We carried the current sum:

TAKE → i + 1, sum + arr[i]
SKIP → i + 1, same sum

Combination Sum

We carry the remaining target:

TAKE → i, target - candidates[i]
SKIP → i + 1, same target

Both representations track progress, but from opposite directions:

Current sum:
0 → 2 → 4 → 7

Remaining target:
7 → 5 → 3 → 0

15. Important Difference: Primitive vs Mutable Object

int target

target - candidates[i]

A new integer value is passed to the child.

No explicit undo.

List<Integer></integer> subList

subList.add(...)

The same mutable object is changed.

Explicit undo required:

subList.remove(...)

Remember:

Primitive value changed for child → parent keeps its old value

Mutable object changed → restore it after recursion

16. Example Walkthrough

candidates = [2,3]
target = 7

Start:

(i=0, target=7, [])

TAKE 2:

(i=0, target=5, [2])

TAKE 2 again:

(i=0, target=3, [2,2])

SKIP 2:

(i=1, target=3, [2,2])

TAKE 3:

(i=1, target=0, [2,2,3])

Base:

target == 0
→ save [2,2,3]

Then recursion returns and:

subList.remove(subList.size() - 1);

restores:

[2,2]

The same pattern continues for other branches.

17. Common Mistakes

Mistake 1 — Incrementing i after TAKE

Wrong:

subsequence(i + 1, ..., target - candidates[i]);

That would prevent reuse.

Correct:

subsequence(i, ..., target - candidates[i]);

Mistake 2 — Subtracting target directly

Avoid:

target -= candidates[i];
...
target += candidates[i];

Use:

target - candidates[i]

as the child argument.

Mistake 3 — Forgetting to remove from subList

Correct:

subList.add(candidates[i]);
subsequence(...);
subList.remove(subList.size() - 1);

Mistake 4 — Using sum and target interchangeably

Choose one representation.

Here:

target = remaining amount

so success is:

target == 0

Core template:

TAKE:
ADD
→ RECURSE(i, target - value)
→ REMOVE

SKIP:
RECURSE(i + 1, target)

The key recursion rule is:

TAKE → stay
SKIP → move


LeetCode 40 — Combination Sum II

Question

LeetCode:
https://leetcode.com/problems/combination-sum-ii/

Given an integer array candidates and an integer target, return all unique combinations where the chosen numbers sum to target.

Important rules:

1. Each element can be used at most once.
2. The input may contain duplicate values.
3. The answer must not contain duplicate combinations.
4. Combination Sum I vs Combination Sum II

Combination Sum I

The same candidate can be used unlimited times.

TAKE  → stay at same index
SKIP  → move to next index

Combination Sum II

Each array element can be used at most once.

TAKE  → move to i + 1

But at each recursion level, the next selected element can be any candidate from the remaining range.

Therefore we use a for loop.

2. Core Pattern

Combination Sum II follows:

FOR EACH POSSIBLE CHOICE

    DO
      ↓
    EXPLORE
      ↓
    UNDO
      ↓
    NEXT CHOICE

Code shape:

for (int i = idx; i < candidates.length; i++) {

    // DO
    subList.add(candidates[i]);

    // EXPLORE
    subsequence(i + 1, ...);

    // UNDO
    subList.remove(subList.size() - 1);
}

This is the classic:

DO → EXPLORE → UNDO

backtracking pattern.

3. Why Is There a for Loop Inside Recursion?

Suppose:

candidates = [1,2,3,4]

At the first recursion level, the next selected element could be:

1
2
3
4

So the conceptual tree starts as:

                         []
                  /      |      |      
                 1       2      3       4

The loop creates these sibling choices:

for (int i = idx; i < candidates.length; i++)

So:

FOR LOOP
↓
enumerates possible choices at the current level

RECURSION
↓
explores the chosen option deeper

4. Does Loop i++ + Recursive i+1 Mean i+2?

No.

They belong to different recursion frames.

Example:

candidates = [1,2,3]

Root:

subsequence(idx = 0)

Parent loop:

i = 0

Choose 1.

Then:

subsequence(i + 1, ...)

becomes:

subsequence(idx = 1, ...)

Now the child has its own loop.

The child may do:

i = 1
i = 2
...

The parent loop is paused while the child is executing.

After the child completely returns, the parent loop resumes and increments its own i.

So:

Parent:
idx = 0
i = 0
choose 1
   ↓
Child:
idx = 1
child loop explores 2, 3, ...
   ↓
Child returns
   ↓
Parent resumes
i++ → 1
choose 2

There is no:

i + 1 + 1 = i + 2

operation.

Instead:

recursive i + 1
===============

child's starting boundary

loop i++
========

parent's next sibling choice

6. Why i + 1 in the Recursive Call?

Combination Sum II says each array element can be used at most once.

Suppose:

candidates = [1,2,3,4]

We choose:

index 1 → value 2

The next recursion starts at:

index 2

because index 1 has already been used.

So:

subsequence(i + 1, ...)

means:

Continue only with elements after the selected element.

This prevents reusing the same array position.

7. Index Reuse vs Value Reuse

Suppose:

candidates = [1,2,2,5]

The two 2s are different array elements:

index 1 → 2
index 2 → 2

Combination Sum II can use both when appropriate:

[2,2]

The rule is:

Same index cannot be reused.
Different duplicate indices may both be selected.

Therefore after choosing index 1, the recursion starts from:

index 2

8. Why Do We Sort?

We use:

Arrays.sort(candidates);

Example:

[1,2,2,5]

The duplicates become adjacent.

Then we can write:

if (i > idx && candidates[i] == candidates[i - 1]) {
    continue;
}

Sorting also allows early stopping:

if (candidates[i] > target) {
    break;
}

because the array is sorted and the candidates are positive.

9. Why Skip Duplicates?

This line:

if (i > idx && candidates[i] == candidates[i - 1]) {
    continue;
}

means:

At the same recursion level, do not start two sibling branches with the same value.

Example:

candidates = [1,2,2,5]

At the root:

                         []
                    /     |                        1      2      5

The two 2s should not create two identical sibling branches:

TAKE first 2
TAKE second 2

So the second 2 is skipped at that level.

10. Why Is i > idx Important?

Duplicates are skipped only at the same recursion level.

Suppose:

candidates = [1,2,2]

After choosing the first 2, the child starts at the next index:

idx = 2

At this deeper level, selecting the second 2 is allowed.

That represents:

[2,2]

using two different array elements.

So:

Same recursion level:
duplicate choice → skip

Different recursion level:
same value at a later index → can be used

11. Why Does subList Need remove()?

subList is a mutable object.

Suppose:

subList = []

Choose 1:

[1]

Explore the entire child branch.

When the child returns, the same list is still:

[1]

But now we want the parent to try another candidate.

So we undo:

subList.remove(subList.size() - 1);

Pattern:

DO
 ↓
ADD
 ↓
EXPLORE
 ↓
REMOVE
 ↓
NEXT CHOICE

12. Why Doesn't target Need Backtracking?

We call:

subsequence(
    i + 1,
    candidates,
    subList,
    list,
    target - candidates[i]
);

target - candidates[i] creates a new int value for the child.

Example:

Parent target = 7

TAKE 2
   ↓
Child target = 5

Child returns

Parent target = 7

So we do not need:

target += candidates[i];

after recursion.

This is different from subList, which is the same mutable object.

13. Complete Recursive Code

class Solution {

    public List<List<Integer></integer>> combinationSum2(
            int[] candidates,
            int target) {

        Arrays.sort(candidates);

        List<Integer></integer> subList = new ArrayList<>();
        List<List<Integer></integer>> list = new ArrayList<>();

        subsequence(
            0,
            candidates,
            subList,
            list,
            target
        );

        return list;
    }

    private void subsequence(
            int idx,
            int[] candidates,
            List<Integer></integer> subList,
            List<List<Integer></integer>> list,
            int target) {

        if (target == 0) {
            list.add(new ArrayList<>(subList));
            return;
        }

        for (int i = idx; i < candidates.length; i++) {

            // Skip duplicate choices at the same level.
            if (i > idx && candidates[i] == candidates[i - 1]) {
                continue;
            }

            // Sorted array: later values will also be too large.
            if (candidates[i] > target) {
                break;
            }

            // DO
            subList.add(candidates[i]);

            // EXPLORE
            // i + 1 because this array element cannot be reused.
            subsequence(
                i + 1,
                candidates,
                subList,
                list,
                target - candidates[i]
            );

            // UNDO
            subList.remove(subList.size() - 1);
        }
    }
}

14. Recursion Tree

Example:

candidates = [1,2,2,5]
target = 5

At the root:

idx = 0

possible choices are:

1
2
2
5

but the second 2 is skipped because it is a duplicate sibling.

Conceptual tree:

                                                                            []
                                 /                    |                    \
                            TAKE 1               TAKE 2               TAKE 5
                                [1]                  [2]                  [5]
                         /   |   \             /     \                 ✓
                 TAKE 2 TAKE 2 TAKE 5   TAKE 2  TAKE 5
                    [1,2]  SKIP  [1,5]     [2,2]   [2,5]
                        /      |      ✓         ✓       X
                ...     duplicate
                                 skipped

The second root-level 2 is skipped because it would create the same sibling
branch as the first 2. However, after choosing the first 2, the child may
choose the second 2 and create [2,2].

Expanded valid and invalid leaves:

[]
├── choose 1 → [1]
│   ├── choose 2 → [1,2]
│   │   ├── choose 2 → [1,2,2]  (sum = 5, valid)
│   │   └── choose 5 → [1,2,5]  (sum > 5, stop)
│   └── choose 5 → [1,5]        (sum = 6, stop)
├── choose first 2 → [2]
│   ├── choose second 2 → [2,2] (sum = 4)
│   │   └── choose 5 → [2,2,5]  (sum > 5, stop)
│   └── choose 5 → [2,5]        (sum > 5, stop)
├── skip second 2                (duplicate sibling at the root)
└── choose 5 → [5]              (sum = 5, valid)

The valid combinations are:

[1,2,2]
[5]

The exact branches depend on the remaining target, but the structure is:

Current recursion level
│
├── choose candidate at i
│   └── child starts at i+1
│
├── choose candidate at i+1
│   └── child starts at i+2
│
├── choose candidate at i+2
│   └── child starts at i+3
│
└── ...

Again, the parent's loop is what creates the siblings.

15. More Precise Tree Meaning

Suppose:

candidates = [1,2,3,4]

Root call:

subsequence(idx=0)

Its loop can choose:

i=0 → 1
i=1 → 2
i=2 → 3
i=3 → 4

So:

                         idx=0
                /          |          |          
              choose1    choose2    choose3    choose4

If the root chooses index 1:

choose 2

the recursive child is:

subsequence(idx=2)

Its loop can choose:

3
4

So:

                    choose 2
                    /       
                 choose 3  choose 4

This is how i+1 prevents the already-used index from appearing below that branch.

16. Why FOR + RECURSION Instead of Simple TAKE/SKIP?

In a simple binary Take/Skip problem:

                     element
                    /                        TAKE       SKIP

There are only two decisions for the current element.

Examples:

Subsets
Subsequence Sum

But Combination Sum II asks:

Which one of the remaining elements should I select next?

That can be:

idx
idx+1
idx+2
...
n-1

Therefore:

for (int i = idx; i < n; i++)

enumerates the choices.

Then recursion explores one choice.

17. The Pattern You Should Recognize

Binary backtracking

Current element
 /            
TAKE          SKIP

Multiple-choice backtracking

Current level
 /    |    |    
A     B    C     D

Code:

for (...) {
    choose(...);
    recurse(...);
    undo();
}

Combination Sum II belongs to the second form.

18. How To Derive This in a New Problem

Do not begin by memorizing:

for (...)

Ask:

Question 1

What am I building?

Combination / subset / path / permutation?

Question 2

At one level, how many choices can I make?

If:

only TAKE or SKIP

then binary recursion may be enough.

If:

any remaining element

then use a for loop to enumerate choices.

Question 3

Can I reuse the chosen element?

Combination Sum II:

NO

so recursive index becomes:

i + 1

Question 4

Am I changing a shared path?

Yes:

subList.add(...)

so:

ADD → RECURSE → REMOVE

Question 5

Can duplicate values create duplicate answers?

Yes.

Therefore:

SORT
+
SKIP DUPLICATE SIBLING CHOICES

19. Tree → Code Translation

Suppose your paper tree says:

                 [current]
                /   |   
               A    B    C

for (int i = idx; i < n; i++) {

A, B, C are possible choices.

21. Most Important i Rule

Remember these are different:

for-loop i++

and:

recursive i+1

for-loop i++

Means:

Try the next sibling at the current recursion level.

Recursive i+1

Means:

The child recursion is not allowed to reuse the element just selected.

Therefore:

Parent loop:
i = 0 → i = 1 → i = 2 ...

Child:
starts at selectedIndex + 1

They are happening in different stack frames.

22. Complexity

Let n = candidates.length.

The recursion can explore many combinations.

Worst-case time is exponential in the number of elements, with additional work for sorting:

Sorting: O(n log n)
Backtracking: exponential in worst case

Auxiliary recursion depth is:

O(n)

The output itself can also be very large.

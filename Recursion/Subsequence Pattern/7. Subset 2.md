
LeetCode 90 — Subsets II

Question

LeetCode:
https://leetcode.com/problems/subsets-ii/

Given an integer array nums that may contain duplicates, return all possible subsets (the power set). The solution set must not contain duplicate subsets. Return the answer in any order. The official examples include nums = [1,2,2] → [[],[1],[1,2],[1,2,2],[2],[2,2]]. Constraints include 1 <= nums.length <= 10 and -10 <= nums[i] <= 10.

1. Main Idea

This is the same backtracking family as Subsets and Combination Sum II.

Core pattern:

FOR EACH POSSIBLE CHOICE

    DO
      ↓
    EXPLORE
      ↓
    UNDO
      ↓
    NEXT CHOICE

Code shape:

for (int i = idx; i < nums.length; i++) {

    subList.add(nums[i]);              // DO

    subset(i + 1, nums, subList, list); // EXPLORE

    subList.remove(subList.size() - 1); // UNDO
}

2. Why Is There a for Loop?

At one recursion level, the next element can be any element from idx onward.

For:

nums = [1,2,3]
idx = 0

the current level can choose:

1
2
3

So the conceptual tree starts:

                         []
                  /       |       
                 1        2        3

The loop creates these sibling choices.

Think:

FOR LOOP
→ enumerate possible choices at this level

RECURSION
→ explore the chosen choice

3. Why i + 1 in Recursion?

Each array element can be used at most once.

Suppose:

nums = [1,2,3,4]

and we choose index 1:

value = 2

The child must start at:

index = 2

so:

subset(i + 1, ...)

This prevents reusing the same array position.

4. Does Loop i++ + Recursion i+1 Mean i+2?

No.

They belong to different recursion frames.

Example:

Parent:
subset(idx = 0)

parent loop:
i = 0
choose 1
    ↓
child:
subset(idx = 1)

child has its OWN loop:
i = 1, 2, ...

child finishes
    ↓
return to parent

parent loop resumes:
i++ → 1

So:

recursive i + 1
===============

child's starting boundary

loop i++
========

next sibling choice in the parent

They do not add together.

5. Why Is There No Explicit Base Case?

This is one of the most important recursion lessons.

Your function does:

list.add(new ArrayList<>(subList));

for (int i = idx; i < nums.length; i++) {
    ...
}

Suppose:

idx == nums.length

Then:

for (int i = nums.length; i < nums.length; i++)

has:

condition = false

So the loop executes zero times.

There are no more recursive calls.

The void function reaches its end and returns automatically.

Therefore the stopping condition is:

idx == nums.length

but it is handled implicitly by the loop boundary, not by an explicit if.

6. Why Do We Save the Answer Before the Loop?

This is the key difference from problems such as Subsequence Sum.

In Subsets II, every current subList is already a valid subset.

Examples:

[]
[1]
[1,2]
[1,2,2]

All are valid subsets.

So we do:

list.add(new ArrayList<>(subList));

at the start of every recursion call.

Then we ask:

Can I extend this subset with more elements?

The for loop does exactly that.

7. Compare With Subsequence Sum

Subsequence Sum

Current partial state:

[1]
[1,2]

is not automatically the final answer.

So we wait until:

i == nums.length

and then check the condition.

Example:

if (i == nums.length) {
    return sum == k;
}

Subsets II

Current state is already a valid answer:

[1]

so:

list.add(copy);

immediately.

Then continue exploring.

Mental rule:

Current state IS an answer
→ save now

Current state is only PARTIAL work
→ keep exploring

8. Why Do We Sort?

We do:

Arrays.sort(nums);

Example:

[2,1,2,1]

becomes:

[1,1,2,2]

Now duplicate values are adjacent.

This allows:

if (i > idx && nums[i] == nums[i - 1]) {
    continue;
}

It also makes a sorted-array early stop possible in related backtracking problems when the remaining values are already too large.

9. Why Skip Duplicates?

Suppose:

nums = [1,2,2]

At the root, we have:

choose 1
choose first 2
choose second 2

If we choose the first 2 and the second 2 as separate sibling branches at the same recursion level, they generate duplicate value-combinations.

So we skip the second 2:

if (i > idx && nums[i] == nums[i - 1]) {
    continue;
}

Important:

We skip duplicate values only as siblings at the same recursion level.

10. Why Is i > idx Important?

Suppose:

nums = [1,2,2]

At root:

idx = 0

The two 2s are siblings.

So:

i = 1 → first 2
i = 2 → second 2

The second 2 is skipped because:

i > idx
AND
nums[i] == nums[i-1]

But after choosing the first 2:

subset(2, ...)

the child starts at index 2.

Now:

i = 2
idx = 2

so:

i > idx

is false.

Therefore the second 2 is allowed.

That creates:

[2,2]

which is correct because those are two different array elements.

11. Same Value vs Same Index

This distinction is extremely important.

index 1 → value 2
index 2 → value 2

Combination/subset problems usually care about array positions being used once, not about banning a value completely.

So:

same index reused
→ not allowed

different duplicate indices
→ may both be selected

12. DO → EXPLORE → UNDO

Your code:

subList.add(nums[i]);

subset(i + 1, nums, subList, list);

subList.remove(subList.size() - 1);

means:

DO
↓
choose nums[i]

EXPLORE
↓
generate all subsets after choosing it

UNDO
↓
restore the previous subset

NEXT
↓
for-loop tries another candidate

This is the same fundamental pattern as Combination Sum II.

13. Why Does subList Need remove()?

subList is the same mutable working list.

Example:

[]

Choose 1:

[1]

Explore everything below [1].

When the child returns, the list is still:

[1]

Before choosing a different sibling, we must restore:

[]

So:

subList.remove(subList.size() - 1);

is the UNDO step.

14. Complete Code

class Solution {

    public List<List<Integer></integer>> subsetsWithDup(int[] nums) {

        Arrays.sort(nums);

        List<Integer></integer> subList = new ArrayList<>();
        List<List<Integer></integer>> list = new ArrayList<>();

        subset(0, nums, subList, list);

        return list;
    }

    private void subset(
            int idx,
            int[] nums,
            List<Integer></integer> subList,
            List<List<Integer></integer>> list) {

        // Every current subList is already a valid subset
        list.add(new ArrayList<>(subList));

        for (int i = idx; i < nums.length; i++) {

            // Skip duplicate choices at the same recursion level
            if (i > idx && nums[i] == nums[i - 1]) {
                continue;
            }

            // DO
            subList.add(nums[i]);

            // EXPLORE
            // i + 1 because an array element can be used only once
            subset(i + 1, nums, subList, list);

            // UNDO
            subList.remove(subList.size() - 1);
        }
    }
}

16. Recursion Tree

For:

nums = [1,2,2]

the important structure is:

                                                            []
                                             /       |       \
                                        choose 1  choose 2  duplicate 2
                                            [1]       [2]       SKIP
                                        /    \       |
                             choose 2  duplicate 2  choose 2
                                 [1,2]       SKIP        [2,2]
                                     |                       |
                             choose 2                 no more choices
                                [1,2,2]

Every node is saved before its children are explored:

[] → [1] → [1,2] → [1,2,2]
             ↓
            [2] → [2,2]

The root-level second 2 is skipped because it would create a duplicate
sibling branch. The second 2 is still allowed below the first 2, because it
comes from a deeper recursion level and represents a different array index.

A more state-oriented view:

subset(idx=0, [])
│
├── i=0 → TAKE 1
│      │
│      └── subset(idx=1, [1])
│             ├── i=1 → TAKE 2
│             │      │
│             │      └── subset(idx=2, [1,2])
│             │             └── i=2 → TAKE 2
│             │                    → [1,2,2]
│             │
│             └── i=2 → duplicate at same level → SKIP
│
├── i=1 → TAKE 2
│      │
│      └── subset(idx=2, [2])
│             └── i=2 → TAKE 2
│                    → [2,2]
│
└── i=2 → duplicate at same level → SKIP

17. Why There Is No return in the Loop

The helper is:

private void subset(...)

so it does not need to return a value.

Its job is:

1. Save current subset
2. Explore children
3. Backtrack

When there are no children:

for-loop runs zero times

and the method naturally returns.

18. Binary vs Multiple-Choice Recursion

Binary

Examples:

Subsets (Take/Skip version)
Subsequence Sum

Conceptually:

                 current
                /                    TAKE       SKIP

Multiple Choice

Examples:

Subsets II
Combination Sum II

Conceptually:

                 current level
             /      |      |                  A       B      C       D

Code:

for (...) {
    choose();
    recurse();
    undo();
}

19. How To Identify This Pattern

When you see a new backtracking problem, ask:

Q1. What am I building?

subset?
combination?
permutation?
path?

Q2. Is the current state already a valid answer?

YES → save/process it now

NO → continue until the answer condition is reached

Q3. At this level, can I choose any remaining element?

YES → for loop

Q4. Can the chosen element be reused?

YES → child may stay at same index

NO → child starts at i + 1

Q5. Does a shared mutable path change?

YES → ADD → RECURSE → REMOVE

Q6. Can duplicate choices create duplicate answers?

YES → sort + skip duplicate siblings

20. Subsets vs Subsets II

Subsets

If all elements are distinct:

TAKE / SKIP

is enough.

Subsets II

Duplicates can generate duplicate subsets:

[1,2,2]

so we add:

SORT
+
for-loop
+
same-level duplicate skipping

The core backtracking remains:

DO → EXPLORE → UNDO

21. Subsets II vs Combination Sum II

Both have:

SORT
FOR LOOP
DO → EXPLORE → UNDO
SKIP DUPLICATE SIBLINGS
i + 1 after TAKE

But their stopping/answer logic differs.

Subsets II

Every current subList is an answer:

list.add(copy);

immediately.

Combination Sum II

A partial combination is not necessarily an answer.

We save only when:

target == 0

22. Base-Case Identification Rule

Do not memorize:

"Every recursion problem must have an explicit if-base-case."

Instead ask:

What does one recursive call represent?

Is the current state already a valid answer?

If yes:
    process/save it now.

If no:
    continue exploring.

When no choices remain:
    does something special need to be calculated?

If yes:
    explicit base case may be needed.

If no:
    the loop boundary may naturally stop recursion.

For Subsets II:

Current state = valid subset
→ save now

No choices remain
→ loop runs zero times
→ return

23. Complexity

For n elements, there can be exponentially many subsets.

Worst-case recursion is exponential:

O(2^n)

Sorting adds:

O(n log n)

The result itself can contain exponentially many subsets, so output size is also exponential.

For this problem the constraint is only:

n <= 10
